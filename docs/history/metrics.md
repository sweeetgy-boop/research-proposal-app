## 계산 방법

- `test_functions_git`·코드 줄 수·파일 수: 해당 커밋의 `git ls-tree`/`git show` 로 센 값(체크아웃 없이, `tools/history_charts.py --recount`
  로 다시 계산 가능). 줄 수는 `src/rra/<계층>/**/*.py` 의 물리적 줄 수(주석·공백 포함).
- `tests_passed_recorded`: PR 본문·`docs/status.md` 에 남은 `pytest -q` 결과. 10-26 이전에는 기록이 없어 비워 두고 test 함수 수로 추이를 본다.
- 자료원 건수: `docs/status.md §5` 와 PR 본문(dev DB `rra sources status`).
- 생성 시간: run manifest 의 첫 단계 시작~마지막 단계 끝(초, 검토 제외). 54초(10-13)는 대화 기록 기준(미검증).
- JSON 성공률: `docs/llm-bench-2026-10-26.md` (b) 최종 성공률.
- Argon 점수: `runs/local/<run>/reviews/review_r*.json` 의 4개 기준(필요성·차별성·실현가능성·기대효과).

## 읽는 법

- 10-27 뒤 행은 `metrics.csv` 의 핵심값만 옮겼다(2026-10-29 문서 최신화). 자료원 칸은 10-29 부터 전체 건수 — 자료원별은 `docs/final-report-materials.md` ⑤.
- 생성 시간은 10-28 오후 Argon 먼저(ADR 0032)로 줄었다가 그림(Nano Banana)이 붙으며 늘었고, 10-29 초안 글 먼저(ADR 0045)로 "초안 글 보임"과 "그림까지"를 나눠 잰다.

- 코드는 adapters 가 가장 크다(외부 연동·파서·DB·렌더가 모두 여기). domain 은 2,700줄 안에서 규칙만 담는다.
- 생성 시간은 7B 로 바뀌며 늘었고(섹션당 6~7초), 근거 20건 전후에서 105~145초. 검토(Argon)는 별도 36초 전후.
- Argon 점수는 같은 입력이라도 run 간 편차(±1)가 있어 한 번의 측정으로 효과를 말할 수 없다 — [Q] 측정은 기준·모두 켬·최종 조합에만 쓴다.
