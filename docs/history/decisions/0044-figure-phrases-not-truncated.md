# ADR 0044 — 그림 칸 글자: 잘라 줄이지 않고 뜻이 완결된 짧은 구절로 (2026-10-29, 레인 B, 시범 의견 3차 항목 2)

## 배경
ADR 0041 의 글자 줄이기(`figure_fit.shorten_spec`)는 그림 글자가 9pt 밑이면 칸 글자를 **띄어쓰기 자리에서 잘라**(22 → 16자) 다시 그렸다.
명세를 받을 때도 `normalize_spec_data`·`techniques._box` 가 30자에서 잘랐다. 그래서 그림에 "신설역 수요를 별도 가정으로", "궤도검측차가 분기별로
측정하고", "준비 단계: 전력 이력 및" 처럼 끊긴 구절이 남았다(10-28 15:54~16:51 시범 측정 run 13건의 그림 47장 중 잘라 줄인 그림 29장,
이번 규칙으로 보면 미완 구절 24개·16장). 소유자 지시: "글자를 잘라 줄이지 말고,
명세를 만들 때 칸마다 글자 수 상한을 주고 그 안에서 뜻이 완결된 짧은 구절로 쓰게 한다. 9pt 미달로 다시 그릴 때도 같은 방식으로 다시 쓴다."

## 결정
1. **칸별 글자 수 상한** (`domain/rules/figure_phrases.FIELD_LIMITS`, 띄어쓰기 포함): As-Is/To-Be 칸 20·가운데 해결 방안 14, 기법 항목·평가 기준 16,
   개념도 설명 줄 20, 체계도 단계 12·산출물 16, 일정표 단계 14, 로드맵 지표 12·목표치 16·단계 12·설명 18, 비교표 칸 18. 수치 그래프는 상한 없음
   (검증 수치 표기 그대로). 기준: 밑그림 본문 글자(37단위 ≈ 10pt)로 1~2줄에 들어가는 길이이면서, pilot2 측정에서 Nano Banana 그림 글자가 9pt 밑으로
   떨어진 길이(SWOT 항목 24~29자 → 5.6~7.1pt, As-Is 칸 30자 → 8.4~8.8pt)보다 짧게. 상한까지 채운 명세도 밑그림에서 9pt 이상·넘침 0
   (`tests/adapters/test_figure_phrase_limits.py` 가 종류 10가지로 고정한다).
2. **프롬프트에 상한과 완결 규칙**: 그림 명세·분석 기법·말로 고치기 프롬프트에 `[칸 글자 수 상한]`(칸마다 N자) + 규칙("명사형으로 끝내거나 완결된 구로,
   초안 문장을 앞에서부터 잘라 옮기지 말고 핵심 낱말을 골라 다시 묶는다, 조사·연결어미로 끝내지 않는다, 말줄임 금지, 낱말은 초안·입력·근거의 말만",
   예 '신설역 수요를 별도 가정으로'(×) → '신설역 수요 별도 가정'(○)). 시스템 프롬프트(figures.md·figure_techniques.md)의 "핵심 구절만 그대로 잘라 쓴다"
   는 지웠다.
3. **검사** (`figure_phrases.problems`): 상한 초과(`figure_phrase_too_long`), 미완(`figure_phrase_incomplete`) — 끝 낱말이 조사·연결어미·관형형(…으로·…를·
   …의·…및·…하여·…하고·…위한·"…ㄹ 수"), 접속어·연결형으로 시작, 말줄임·끊긴 기호·닫히지 않은 괄호, **낱말 중간 끊김**(근거 글자에 그 낱말이 조사·어미를
   붙인 꼴로도 없고 더 긴 낱말의 앞부분으로만 있다, 예 "…별도 가" ← "가정으로"). '효과·결과·회의·선로·피해' 처럼 끝 글자가 조사와 같은 명사는 목록과
   근거 대조(같은 줄기가 다른 조사로도 쓰였는가)로 거른다. 고정 글자("정보 없음"·"목표치 확인 필요"·"산출 필요")는 검사하지 않는다.
4. **순서**: 모델 답 → 정리(띄어쓰기만, **자르지 않음**) → 칸 글자 검사 → 걸리면 같은 모델에 교정 재요청 1회(어느 칸이 왜 걸렸는지·상한을 알려 준다)
   → 그래도 남으면 **규칙 대체**(`salvage`): 그 칸 글자 안의 연속한 온전한 낱말 묶음 중 완결되고 상한 안이며 출처에 있는 것 — 끝 낱말(구의 머리)을
   지키는 묶음 → 긴 것 순, 끝 낱말의 조사·어미만 덜 수 있다(낱말은 자르지 않는다). 없으면 빼도 되는 칸(설명 줄·산출물·기법 항목·4번째 As-Is 칸)은
   빼고, 아니면 명세를 받지 않는다(기존 "다음 모델" 순서). 모델 순서는 그대로 Argon → 오류면 로컬(`_ask`).
5. **9pt 미달 다시 그리기 = Argon 다시 쓰기** (`MakeFigures.rewrite_texts`): OCR 로 잰 그림 글자(또는 밑그림 글자)가 9pt 밑이면 칸 글자를 상한 × 0.75
   (`TIGHTEN`; As-Is 칸 15·해결 방안 10·기법 항목 12) 안의 완결 구절로 다시 쓰게 한다(`[그림 글자 다시 쓰기: 종류]`, 답 `{"texts":[{path,value}]}`,
   칸 구조·출처 id·등급은 그대로). 다시 쓴 글자도 같은 검사(완결 규칙 + `validate_spec` 출처 — 초안·입력·근거 + 현재 그림 글자)를 거치고, 교정 뒤에도
   걸린 칸은 원래 글자의 온전한 낱말 묶음, 그것도 없으면 원래 글자 그대로 둔다. 이미 줄인 상한 안이면 부르지 않는다(글자가 커지지 않는다 — "글자를 더
   크게" 만). As-Is/To-Be 이름표 두 글자(방안·효과)는 정해진 낱말이라 그대로 쓴다(`shorten_tags`). 밑그림부터 다시 그린 뒤 Nano Banana 1회.
6. **`max_image_redraws` 2 → 1** (figures.yaml·config_loader 기본값·FigureConfig). 글자 줄이기 단계(`max_shorten`)·`shorten_spec`·`clip_words`·
   `clip_text` 는 지웠다.
7. 제안자 글자는 다시 쓰지 않는다: [글자 고치기](shorten=False)는 기록만, [말로 고치기]는 요청에 적힌 글자와 이미 받아들인(현재 명세) 글자를 칸 글자
   규칙에서 빼고(`exempt`), 다시 그릴 때도 요청 글자가 든 칸은 다시 쓰지 않는다(`protect`).

## 결과
- 측정: `docs/eval-2026-10-29-figure-phrases.md` (시범 골든 run 5건 사본, Argon 명세 → Nano Banana → OCR) — 그림 13장 글자 9pt 이상 13/13
  (최소 9.0·중앙 10.1pt), 최종 미완 구절 0(같은 run 이전 그림 9장은 14개), 다시 그린 그림 1/13, 장당 중앙 54초.
- 실측에서 "명사형으로 끝내라" 와 출처 낱말 검사가 부딪혀 그림 1장이 빠졌다 → 근거 동사의 명사형(못하…→못함, 남는…→남음, …되→…됨)은 출처로
  인정하고(`TextPool.has_text`), 교정 뒤에도 출처 밖 낱말이 든 칸은 그 칸 안의 출처 낱말 묶음으로 바꾼다(`salvage(also=)`). 한자어 바꿔 쓰기
  ('잔존·미추적')는 여전히 거절.
- 기록: `Figure.fit.shortened` 는 이제 "다시 쓴 칸 수"(잘라 줄인 칸 수가 아니다). API·화면 필드는 그대로.
- 대가: 상한 때문에 As-Is/To-Be 3칸은 대부분 21:9(낮고 넓게)가 된다. 교정 재요청·다시 쓰기로 그림 한 장에 Argon 텍스트 호출이 1 → 1~3회.

## 대안
- 상한만 주고 넘으면 자른다 — 소유자가 거부한 방식.
- 다시 그릴 때 Nano Banana 에 "글자를 더 크게" 만 — pilot2 에서 긴 칸 글자는 그래도 5~7pt 였다(내용 양이 원인).
