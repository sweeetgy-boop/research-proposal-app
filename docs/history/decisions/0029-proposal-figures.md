# ADR 0029 — 제안서 그림은 "명세 → 밑그림 → Nano Banana Pro 1회", 자동 검증 대신 제안자 확인 (2026-10-28, [G])

## 배경
별지 제2호서식 제안서는 글만으로 채워졌다. 심사자가 한눈에 보는 개념도·체계도·일정표·현황 그래프·비교표·로드맵을
초안과 함께 자동으로 넣고 싶지만, (1) 이미지 생성 AI 는 글자·숫자를 지어내고, (2) 사내 자료의 수치·과제명이 외부로 나가며,
(3) 양식(HWPX) 칸 안에 그림을 넣으면 줄 배치가 깨질 수 있다.

## 선택지
1. 템플릿 SVG 만 (이미지 AI 없음) — 안전하지만 보고서용 완성도가 낮다.
2. 이미지 AI 에 자유 프롬프트 — 완성도는 높지만 글자·수치를 통제할 수 없다.
3. **구조화된 명세(JSON) → 템플릿 SVG 밑그림 → 밑그림을 참고 이미지로 Nano Banana Pro 1회 → 채택**, 글자는 명세 목록을 그대로 쓰게 지시.
   OCR 로 자동 대조·재시도(처음 지시) vs 제안자가 카드에서 직접 확인·수정(최종 지시).

## 결정
- 3번. 명세의 글자·수치는 **초안 본문·제안자 입력·근거 청크·검증된 table_facts 에 있는 것만** 허용한다(`domain/rules/figures.validate_spec`).
  수치 그래프는 출처 문서의 table_facts 값만, 일정표는 연구기간(제약) 안에서만. 위반 명세는 그리지 않는다.
- 자동 검증(OCR 대조·재시도)은 **하지 않는다**. 그림마다 "확인 전" 배지 → 제안자가 [확인함]. 고치면(말로 고치기·글자 고치기·기본 그림으로·
  다시 만들기) 다시 "확인 전". 제출 전 점검에 "확인 전 그림 n개", 최종 마무리 때 확인 창. 카드에 "AI 가 그린 그림입니다. 숫자와 글자를
  원문과 확인하세요" 안내.
- 호출 실패(오류·응답 없음·일일 상한)일 때만 밑그림을 "기본 그림"으로 채택. 외부로 나가는 것은 명세 글자 목록 + 밑그림(또는 현재 그림)뿐.
  공용 계정은 internal 근거에만 있는 글자가 든 명세를 폐기한다. 그림 호출은 Gemini 공용 제한기 + 별도 일일 상한
  (`figures.daily_image_cap` 150, 생성·고치기 포함) + 같은 (모델·프롬프트·참고 이미지) 캐시.
- 그림은 버전(`DraftVersion.figures`)의 일부다 — 카드 동작마다 새 버전, 복원하면 그 버전의 그림(파일은 해시 이름으로 남는다), 비교에 "그림 변경".
- Argon 1차 검토에 그림 명세를 함께 보내 "본문과 그림이 어긋나는 곳"만 지적(`figures` 응답, kind=figure 의견) — 호출 수 증가 없음.
- HWPX: 섹션 본문 마지막 줄에 표식 단락을 넣어 치환한 뒤 그 자리에 그림(BinData)+캡션(`그림 n. …`)+출처 단락. 실물 양식은 본문이 표 밖 단락이라
  본문 바로 뒤에 들어간다. 표식을 못 찾거나 설정이 appendix 면 "(별첨 그림 n 참조)" + 문서 끝 "별첨 그림". 방식은 manifest `figures[].placement`.
- 이미지는 저장 전 500KB 이하로 축소(JPEG 품질·긴 변 2000px). 폰트는 번들 Pretendard 서브셋, 색은 명도 4단 + 무늬(흑백 인쇄 구분), 로고·사진 금지.
