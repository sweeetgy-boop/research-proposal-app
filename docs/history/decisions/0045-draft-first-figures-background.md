# ADR 0045 — 초안 글 먼저, 그림은 백그라운드 (2026-10-29, 레인 C)

> 브랜치 feat/draft-first-figures-bg. 소유자 지시 3 "생성 시간".

## 배경
- 지난 측정(docs/eval-2026-10-28-pilot2.md): 생성 중앙 217초 가운데 그림 단계가 중앙 123초(84~163)였다. 그림은 v1 을 저장한 뒤
  `_figures_step` 에서 그렸고, 그동안 상태는 running — 제안자는 글이 다 써졌는데도 그림이 끝날 때까지 초안을 못 봤다.
- drafted 로 먼저 바꾸지 않은 이유(10-28 시험): 생성 실행이 들고 있던 RunState 를 마지막에 통째로 저장해서, 그 사이 제안자의 편집
  (draft_version 등)이 덮어써졌다. 그림을 그리면서 run 락도 쥐고 있었다.

## 선택지 (그림이 도착할 자리)
1. 다 그린 뒤 run 락 안에서 현재 버전 파일에 바로 넣는다 — 단순하지만 그리는 동안 v2·v3 이 생기면 어느 버전에 넣을지, 넣는 순간
   편집과 겹치면 무엇이 이기는지가 흐려진다.
2. **run 마다 그림 작업 파일(figures_job.json) 하나 + 읽을 때 합치기, 작업이 끝나면 그동안 만든 버전 파일에 한 번 채우기.**
3. 그림이 올 때마다 새 버전 — 그림 때문에 "변경 n건"·버전 목록이 늘어난다(ADR 0042 와 어긋남).

## 결정
2.
- 시작: `_execute` 가 v1 을 저장하고 drafted 로 바꾸기 직전에 그림 작업 락(`.figures.lock`, run 락과 따로)을 잡고 작업 파일(자리 목록)을
  쓴다 → 상태를 저장하고 run 락을 놓은 **뒤에** TaskRunner 로 작업을 띄운다(key `<run_id>:figures`). 생성 칸(run_slot)·전역 슬롯은 잡지
  않는다. 명세의 로컬 대체만 그림 유스케이스가 전역 슬롯을 잡는다(local_held=False — 로컬 작성 run 도 이제 슬롯을 놓은 뒤 다시 잡는다).
- 도착: 기본 그림은 자리마다 따로(`MakeFigures.plan` + `build_all([한 장])`, 같은 채우기 규칙 — 걸러진 만큼 우선순위 다음 종류로 한 번)
  그려 한 장씩 작업 파일에 넣는다. 분석 기법 추천(0~2장)은 개수를 몰라 자리 하나("분석 기법 추천 그림"). 넣는 구간은 await 없는 동기
  구간이라 같은 프로세스의 다른 동작이 끼어들 수 없다. id 가 겹치면(작업 안·현재 버전) 새 id 를 준다.
- 합치기: `_version()`(버전 + 상태 표시를 합치는 곳, ADR 0042)이 표시보다 먼저 작업 그림을 합친다. **버전에 이미 있는 그림이 이긴다**
  (제안자가 도착한 그림을 고쳤을 수 있다). 그림 때문에 내용 버전이 생기지 않고, 그리는 동안 저장한 v2·v3 의 문장은 그대로다.
- 끝: 그동안 만든 버전 파일(base_version 이상)에 그림을 한 번 채우고(`applied`), 그 뒤로는 합치지 않는다. 버전 파일을 고치는 유일한
  예외다 — 그 버전들은 처음부터 화면에서 그 그림을 보였으므로(읽기 합치기) "그 버전이 무엇이었나" 는 달라지지 않는다.
- 상태는 RunState 가 아니라 작업 파일에 — 다른 동작이 들고 있던 옛 상태를 저장해도 그림 진행이 되돌아가지 않는다. 읽을 때
  (`_normalize`) `figures_status`(pending|drawing|done|failed)·`figure_slots`(그리는 중·실패, 그림이 한 장도 없으면 걸러진 자리도)·
  `draft_visible_seconds`·`figures_done_seconds` 와 그림 단계(step figures)를 채운다.
- 재시작: 작업 상태가 그리는 중인데 이 프로세스에 작업이 없고 그림 락도 풀려 있으면 읽는 순간 failed(`interrupted`) — 그리던 자리는
  실패 카드("서버가 다시 시작되어 그리지 못했습니다 (호출 실패)" + [다시 그리기])로 남고, 도착한 그림은 버전에 채운다. 영원히
  "그리는 중" 인 run 은 없다. 이어 그리기(재개)는 하지 않는다 — 명세·그림 호출을 처음부터 다시 하는 것과 같아 [다시 그리기]로 충분하다.
- 막기(한국어 안내): 그리는 중인 자리(`slot-n`)의 동작 → "이 그림은 아직 그리는 중입니다 …", 그림 추가·[다시 추천] → "그림을 그리는
  중입니다 — 끝난 뒤 …"(그리는 그림과 id 가 겹치지 않게), ⑤ 최종 검토·⑥ 마무리 → **"그림 준비 중 — 끝나면 진행할 수 있습니다."**
  (그림이 빠진 HWPX·검토를 내지 않는다. 화면 버튼도 같은 문구로 막는다). 도착한 그림의 확인·고치기, 문장 편집·AI 다시 쓰기는 그대로.
  작업이 failed 면 막지 않는다(그림 없이 진행 가능, 카드가 [다시 그리기]).
- ③ 1차 검토(review.first_pass, 운영은 off)가 켜져 있으면 그림까지 보도록 그림이 끝난 뒤 자동 시작한다.
- 운영: `rra runs active` 가 그림을 그리는 run 도 센다(`figures_status`, "drafted (그림 그리는 중)") → `tools/deploy.sh --wait` 가 그림
  작업을 끊지 않는다. CLI `rra generate`·`rra eval` 은 `RunManager.wait` 가 그림 작업까지 기다린다.
- 시간: `draft_visible_seconds`(제출 → drafted), `figures_done_seconds`(제출 → 그림 끝; 그림이 없으면 같은 값) — RunState·usage.json·
  manifest `timing`(숫자·코드만), GET /v1/runs/{id}.
- 작성 중 섹션 먼저 보기: 섹션은 이미 섹션마다 체크포인트(sections/<key>.json)로 저장된다. `GET /v1/runs/{id}/sections-progress` 가 그
  글(읽기 전용, 버전 아님, 마무리 정리 전)과 남은 섹션 키를 주고, 진행 화면이 2초마다 "작성됨"·"작성 중" 으로 보인다.
- 화면: 상태 조회가 그리는 동안 2초마다(SSE 는 생성·검토 중에만), 그림 작업 표식이 바뀌면 초안·그림 목록·점검을 다시 읽는다. 섹션 그림
  자리에 "그림 준비 중" 카드(`FigureSlotCard`), 위쪽 한 줄 "그림 준비 중 · n장 준비됨 · m장 그리는 중"(`FigureJobBanner`, 섹션을 모르는
  기법 추천 자리도 여기), 실패면 사유 + [다시 그리기](같은 종류·섹션으로 그림 추가) 또는 [다시 추천].

## 결과
- 가짜 테스트: 그리는 동안 drafted·run 락 풀림·그림 락만, 한 장씩 도착, 그리는 중 편집 → 그림이 v2 에 들어가고 편집 그대로·버전
  [1, 2], 자리 동작·추가·추천·최종 검토·마무리 거부, 재시작 → failed·실패 카드, runs active 에 그리는 run, 시간 기록(usage·manifest).
