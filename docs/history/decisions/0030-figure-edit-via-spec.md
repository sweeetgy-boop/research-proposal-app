# ADR 0030 — [말로 고치기]는 그림 편집이 아니라 "명세 변경 → 밑그림 → 새로 그림", 명세는 Argon 먼저 (2026-10-28, [2])

## 배경
ADR 0029 의 [말로 고치기]는 현재(채택) 그림 + 요청을 Nano Banana Pro 편집 호출에 넣었다. 오전 실측에서 요청은 반영됐지만
그림 속 글자가 바뀌었다 — 명세 글자 목록 없이 3곳("상태→샹태"·"에만→에안"·"대응→대용"), 목록을 넣어도 2곳(+ 상자 테두리 끊김).
이미 한 번 다시 그린 JPEG 을 또 다시 그리는 방식이라 글자 변형이 쌓인다. 또 배포 시험에서 로컬 7B 가 쓴 명세는 근거 밖 단계·글자가 많아
초안 1건당 그림이 1~2장(목표 3)에 그쳤다.

## 선택지
1. 편집 호출 유지 + 글자 목록·OCR 대조 재시도 — 변형이 줄어도 0 이 되지 않고, 호출·시간이 늘어난다.
2. **요청을 명세 변경으로 바꾼 뒤(텍스트 LLM) 밑그림에서 새로 그린다** — 첫 생성과 같은 경로라 글자 정확도가 첫 생성 수준.
   모양만 바꾸는 요청(색·굵기·여백)은 명세를 그대로 두고 밑그림 + 모양 요청으로 다시 그린다.

## 결정
- 2번. `MakeFigures.edit_by_words`: 요청(`privacy.strip_personal` 뒤) + 현재 명세 JSON + 종류 스키마 + 글자 목록 → Argon(review 단계 provider·모델,
  `build_llm(stage="review")` = 예산 래퍼) 1회 → `{"spec", "style", "summary"}`. 오류·429·예산이면 로컬 모델(figures 단계). 모델마다 교정 재요청 1회.
- 새 명세는 생성과 똑같이 `normalize_spec_data → repair_spec → validate_spec`. pool 은 run 의 pool(`MakeFigures.pool`) + **현재 명세 글자 + 요청 원문**
  (`rules.with_texts`) — 제안자가 요청에 적은 글자는 [글자 고치기]와 같이 받아들이고, 그 밖의 새 글자·수치는 거절한다. 위반·변경 없음(`no_change`)이면
  `SpecRejected(사유 코드)` → REST 409(사유 + 안내 한 문장), 버전·그림 호출 없음.
- 그림은 `draw()` 그대로: 새 명세 → 밑그림(SVG→PNG) → Nano Banana `generate`(참고 이미지 = 밑그림, 프롬프트 = `image_prompt` + 글자 목록, 모양 요청은
  덧붙임). **현재 그림은 모델에 보내지 않는다**(포트의 `edit` 는 남겨 두지만 쓰지 않는다). 명세가 바뀐 요청은 그림 호출이 실패하면 새 밑그림을
  채택(첫 생성과 같음), 모양만 바꾸는 요청은 실패하면 거절(기본 그림으로 바꾸지 않음).
- 결과 `Figure.last_change {kind: content|style, summary[], style, model, at}` — 카드 "바뀐 내용". 요약은 모델 줄을 쓰되 `repair_spec` 이 덜어 낸
  글자가 있으면 규칙 비교(`rules.spec_change_summary`, SequenceMatcher)로 바꾼다. [글자 고치기]도 같은 필드에 규칙 요약을 남긴다. 고치면 "확인 전".
- 초안 생성 때 명세도 Argon → 로컬(→ compose.fallback 은 review 키가 없을 때만) 순서. 쓴 모델은 `Figure.spec_model`. 공용 계정은 기존대로 internal 청크를
  프롬프트에서 빼고 internal 에만 있는 글자가 든 명세는 폐기. 외부로 나가는 것: 초안 본문·입력·인용 근거(검토와 같은 범위, `external_llm.include_internal`).

## 결과 (2026-10-28 오후)
- 측정 `docs/eval-2026-10-28-figure-edit.md` — 같은 요청 3개 × 2회, 글자 변형(OCR + 눈 대조)·시간.
- 테스트: 유스케이스 +7(명세 변경·모양만·거절·Argon 실패 → 로컬·명세 생성 순서·요약 대체·명세 변경 + 그림 실패), RunManager +1, 규칙 +2, API·카드 갱신.

## 후속
- 7B 로컬 대체가 명세 변경을 얼마나 지키는지는 mlx 를 띄운 측정에서 잰다(이번 시험은 Argon 만).
- 개념도 상자 이름은 `repair_spec` 이 템플릿 라벨로 고정하므로, [글자 고치기]로 바꾼 상자 이름은 다음 [말로 고치기]에서 템플릿 라벨로 돌아간다.
