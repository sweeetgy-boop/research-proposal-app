# ADR 0034 — HWPX 서식은 단계별 단락 모양으로 맞추고, 만들 때마다 점검·고친다 (2026-10-28)

> 레인 D(feat/format-ui). 번호는 합칠 때 다른 레인과 겹치면 다시 매긴다.

## 배경
시범 HWPX 를 열어 보니 줄바꿈된 둘째 줄이 왼쪽 끝으로 돌아가고(공백 들여쓰기), 한 장 안에서 단락 모양이 섞이고(3장 가. 만
내어쓰기), 글자 크기가 섞였다(특이사항 본문 13pt 굵게, 그림 캡션 17pt). 원인은 템플릿 변환(tools/build_form_template.py)이
제목 단락을 복제해 본문 자리를 만들고 공백으로 들여썼기 때문이다. 템플릿 파일은 커밋하지 않고 운영기에서 한 번 만든 것을 쓴다.

## 선택지
1. 템플릿 변환 스크립트를 고쳐 새 템플릿을 만든다 — 운영기에서 사람이 다시 만들어야 하고, 그림 캡션(렌더 때 생김)은 못 고친다.
2. **렌더 결과를 받아 단락마다 단계(장·항목·세부·줄표·○·안내·캡션·표 칸)를 정하고 header.xml 에 단계별 단락 모양을 더해
   맞춘다** — 템플릿은 그대로, 매번 점검하고 결과를 남긴다.
3. python-hwpx 객체 모델로 다시 쓴다 — 템플릿 모드는 문자열 치환(보안 F 검증 경로)이라 두 길이 생긴다.

## 결정
2. `adapters/rendering/hwpx_format.py` 의 `format_hwpx` 를 `HwpxRenderer.render`·`render_with_figures` 끝(verify_hwpx 직전)에서
돌린다. 단계 표·값은 eval 문서(docs/eval-2026-10-28-hwpx-format.md §2). 고친 뒤 다시 점검해 남은 불일치를 `remaining` 으로,
고친 단락 수를 종류별로 `fixed` 로 — 마무리 때 `RunState.hwpx_format` → manifest(허용 키·정수만) + 로그 `run.hwpx_format`.
렌더러의 `expand_paragraphs` 는 자리표시자 앞 공백을 버린다. `format_check: false` 로 끌 수 있다(조립 인자).

## 이유
- 운영기 템플릿을 다시 만들지 않아도 바로 적용되고, 양식이 바뀌어도 머리표 규칙만 맞으면 따라간다.
- 글자를 넣지 않는다(공백 제거·모양 id 변경·모양 복제) — 보안 F 의 escape·재파싱 경로를 건드리지 않는다.
- 같은 모양은 재사용해 멱등이다(두 번 돌려도 고칠 것 0, 모양 추가 0).

## 결과
- 골든셋 10건 10/10, 시범 run 19건 19/19 남은 불일치 0 (그림 포함 9건 캡션 12pt 가운데).
- 한/글 화면 확인 전 — 내어쓰기 폭은 어림값(머리표+공백 ≈ 1.5글자)이라 운영기 한컴오피스에서 1건 열어 확인한 뒤 `LEVELS` 값만 조정.
- 생성 모드(템플릿 없음)는 단계 단락이 없어 캡션·표 칸·앞 공백만 본다.
