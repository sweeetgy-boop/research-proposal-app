# ADR 0012 — 차별화 과제 추천 0~5건 (2026-10-27)

**배경** 유사과제 확인에서 "차단" 만 알려 주면 제안자는 방향을 바꿀 재료가 없다. 기존 차별화 제안(기능 2)은 차단 알림일 때만 자동.
**선택지** (a) 기존 차별화 제안 확장, (b) 별도 "과제 추천" 유스케이스(0~5건, 비교 과제·근거·위험 포함), (c) 추천 없음.
**결정** (b). precheck 뒤 자동 1회(Gemini, 키 없으면 로컬), 검증(doc_id 는 이번 검색·precheck 안, 지어낸 수치·정책명 lint, 자기 중복 precheck 로 blocking 제외), 추천할 것이 없으면 사유만.
**이유** 제안자 아이디어의 목적 안에서 "기존 과제와 다른" 방향을 근거와 함께 주되, 억지 추천은 하지 않는다.
**결과** [R] 브랜치 feat/project-recommendations, PR #21. 실측(골든셋, Gemini 4 Argon, 2026-10-27, 4회 반복):
- 03 철도 무관: 4회 모두 추천 0 + 정확한 사유("적용 대상·목적이 완전히 다름, 관련 근거 부족"). 의도대로.
- 01 궤도·02 자산개발: 모델은 매번 2건씩 냈으나 1~3차에서 전부 검증 제외. 원인 두 가지를 고쳤다 — (a) compared_with 가
  알림 id 만 허용해 모델이 비교 대상으로 든 검색 논문이 폐기됨 → 지시서대로 검색 근거 id 도 허용, (b) 자기 중복 검사:
  probe 에 원래 입력 4칸을 섞으면 원래 아이디어가 차단될 때 전부 떨어지고, 추천 글만으로 바꿔도 e5 가 같은 분야 한국어
  글을 모두 0.84~0.87 로 올려 "차단이면 제외" 가 모든 추천을 뺀다. 상대 기준(원래보다 멀어졌을 때만 통과)으로도 같음.
- **결정(보수적 완화)**: 자기 중복 검사는 유지하되 결과를 기본 **경고**로(`recommend.self_overlap: warn`, 카드·CLI·API 에
  "겹칠 수 있음: doc_id") — 중복 최종 판단은 사람이 한다는 앱 원칙과 같다. 지시서 원문의 제외는 `exclude` 로 한 줄 전환.
  reranker(Q8) 로 precheck 정밀도가 오르면 exclude 를 재검토한다.
- 4차(warn): 01 추천 2건(각각 비교 과제 3건·근거 3~4건·위험 1건, 겹칠 수 있음 8·9건), 02 추천 1건(+1건 정책명 ungrounded
  폐기), 03 0건. Gemini 호출 13회(llm-check 1 + 4회×3).
