# ADR 0042 — 상태 표시는 버전을 만들지 않는다 · 단계 화면 아래 이동 막대 · "run" 표기 (2026-10-28 밤, 레인 D)

> 브랜치 feat/versions-nav. 시범 의견 2차 항목 21·22·25.

## 배경
- 시범 run 4건에서 그림 [확인함] 을 누를 때마다 새 버전이 생겼다(v2~v4 가 모두 "그림 confirm", 본문은 v1 과 같음).
  `runs/staff-…/20261028115815-61acbe6d` 는 v1 뒤 확인 3번 = 버전 3개. 근거 승인 한 번도 "근거 판단" 버전(v7)이 되었다.
  버전 목록 "바뀐 섹션" 에는 그림이 붙은 섹션 이름이 나왔지만 그 섹션 본문은 바뀌지 않았다.
- 버전 메모에 "그림 confirm" 처럼 내부 동작 이름이 그대로 보였다. v1 배지는 Argon 이 써도 "로컬 생성".
- 단계 사이를 오가려면 위쪽 단계 표시나 탭을 찾아야 했고, 남은 확인(그림·추천 그림 결정)이 어디 있는지 몰랐다.
- 화면 곳곳에 "run 목록·run 번호·옛 run" 같은 내부 용어가 보였다.

## 선택지 (상태 저장)
1. 현재 버전 파일을 바로 고친다 — 단순하지만 버전 파일이 바뀌어 "그 버전이 무엇이었는가" 가 흐려지고, 비교 기준(마지막 검토 버전)이
   나중 확인을 품게 된다.
2. **버전 파일은 그대로 두고, 버전마다 표시 파일(`versions/marks_vN.json`, `VersionMarks`)에 쌓는다. 읽을 때 합친다.**
3. run 하나에 표시 파일 하나 — 버전과 표시의 대응이 사라져 복원·비교가 어려워진다.

## 결정
2.
- 상태 표시(버전 없음): 그림 [확인함], 추천 그림 [넣기 확정]·[필요 없음]·[다시 넣기], 근거 승인·제외(일괄 승인 포함), 선택형 확정
  (기록만), 로컬 검토 제안 [무시](레인 B — `RunManager.record_mark(kind="suggestion_ignore")` 로 같은 기록에 남긴다).
- 내용 변경(새 버전): [새 버전으로 저장], AI 다시 쓰기 반영, 그림 다시 그리기·말로 고치기·글자 고치기·기본 그림·기법 바꾸기·추가·
  빼기·넣기(추천이 아닌 그림), 근거 교체, 로컬 검토 제안 [반영], 복원, 입력 변경 다시 쓰기, 정책 근거 선택.
- 규칙 `domain/rules/status_marks.py`(apply_marks·mark_figure·mark_evidence·add_log·carry_figure_marks·status_only_marks), 모델
  `domain/models/marks.py`, 포트 `RunStorePort.save_marks/load_marks`, RunManager 섞어 쓰기 `services/status_marks_mixin.py`.
  읽기(`_version`·`_current_version`·get_draft·versions·get_version·`_figure_files`·manifest)는 버전 + 표시를 합친다 → 화면·제출 전
  점검·마무리(HWPX)·manifest 가 늘 최신 표시를 본다. 새 버전은 합친 현재 버전에서 만들므로 표시가 새 버전 파일에 들어간다.
  표시한 뒤 그림이 바뀌면(image_sha 다름) 그 표시는 적용하지 않는다(새 그림은 다시 확인). 복원은 같은 그림(id·해시·명세)의
  지금 표시를 이어받는다. `_refresh_problems` 는 버전 파일의 알림 수만 고치고 표시는 넣지 않는다.
- 상태 표시는 run 상태(drafted·final_reviewed …)를 바꾸지 않는다 — 최종 검토 뒤 그림을 확인해도 "최종 검토 이후 수정" 이 아니다.
- "변경 n건"(`change_count.total`)은 내용만, 상태 표시는 "확인 n건"(`confirmations`, `confirm_items`). 기준 버전은 표시 없는 버전 파일,
  현재 버전은 합친 것.
- 버전 목록(`domain/rules/version_history.py`): 바뀐 섹션은 이전 버전과의 실제 차이(문장·선택값)로만, 바뀐 그림은 이름으로
  ("연구 개념도 다시 그림"), 확인 기록은 문구로("그림 확인 — 분석 기법 그림 – SWOT 분석"). 예전 run 의 상태만 바뀐 버전은 지우지 않고
  `status_only` 로 표시해 화면이 "확인 기록" 으로 접는다. 메모 "그림 <동작>" 은 한국어로, 새 메모는 처음부터 "그림 다시 그리기 — 이름".
  v1 배지는 실제 작성자: "Argon 작성" / "Argon 작성(일부 로컬)" / "로컬 작성"(writer 기록 없는 예전 run 은 "로컬 생성" 그대로).
  그림 이름은 레인 C 의 `Figure.display_name` 이 있으면 그것, 없으면 종류·기법 이름(`figure_name`).
- 아래 이동 막대(`web/src/components/StepNavBar.tsx`): 왼쪽 [← 이전 단계: ○○], 오른쪽 [다음: ○○ →], 가운데 남은 일(제출 전 점검의
  실패 항목 — 확인 전 그림 n장·추천 그림 결정 n건·로컬 검토 불일치 n건 …). 남은 일은 막지 않고 넘어갈 때 한 번 알린다. ② 게이트만
  막는다(이유 표시). 높이는 `:root --stepnav-h`. run 안에서는 `RunStepBar` 가 `lib/runSteps.runStepNeighbors` 로 위쪽 단계 표시와
  같은 표(runStepTargets)를 쓴다 — 단계 표시·탭·막대가 늘 같은 단계. 초안 보기에 [수정 없이 최종 검토로].
- ⑤ 최종 검토·선행연구 브리핑 대기: 경과 초 + [취소](ADR 0038 공용 부품). 최종 검토 [취소] = `POST /v1/runs/{id}/final-review/cancel`
  (백그라운드 검토 작업 취소 → 검토 전 상태, 결과·버전 없음), 브리핑은 `cancel_on_disconnect`.
- 화면의 "run" → "제안서·작성 번호·작성 상태·내 제안서". e2e `expectNoRunWord` 가 화면마다 확인한다.

## 이유
- 확인은 내용이 아니다. 버전은 "무엇이 바뀌었나" 를 비교·복원하는 단위로 남긴다.
- 표시 파일을 버전마다 두면 버전 파일은 만든 뒤 그대로이고, 어느 버전에서 무엇을 확인했는지도 남는다.

## 결과
- 가짜 LLM 테스트: 그림 확인 ×3 → 버전 수 그대로·화면/점검/마무리에 반영, 추천 결정·근거 승인도 버전 없음, 변경 0건·확인 n건,
  예전 상태만 바뀐 버전 접기, 실제로 바뀐 섹션만, v1 작성자 배지, 최종 검토 [취소]. e2e `web/e2e/versions-nav.spec.ts`.
