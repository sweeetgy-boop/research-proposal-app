# ADR 0052 — ① 정책 근거 추천 팝업: 1순위 미리 체크, [적용] 해야만 칸에 들어감 + 나중에 다시 넣는 길 (2026-10-29, feat/policy-popup)

## 맥락
- 시범 사용 의견(2026-10-29): ① [정책 근거 추천]을 직접 눌러야만 추천이 나와서, 누르지 않고 넘어가면 2-가-(1) 정책적 중요도가 빈칸으로 생성됐다.
  나중에 다시 넣는 방법도 찾지 못했다.
- 시범 제안서 11건을 상태·문장 수로만 셌다(내용은 보지 않음). 정책 근거 없이 만든 7건 가운데 6건이 2-가-(1) 빈칸이었고, 그중 2건은 그대로 마무리됐다.
  편집을 여러 번 한 제안서도 빈칸이었다.
- ④ 직접 수정의 [정책 근거 고르기] 단추는 그려지고 있었다(가짜 모드, 1280px·390px 확인). 빈 섹션도 문장 0개로 버전에 들어간다. 찾지 못한 원인은 셋이다.
  1. 생성 직후 먼저 보는 ③ 초안 보기에는 빈 2-가-(1)을 채울 단추나 길 안내가 없었다. "직접 수정에서 채울 수 있습니다" 한 줄과, 어디로 가라는 말 없는 알림뿐이었다.
  2. ④에서 빈 섹션은 머리줄만 있고 본문 자리가 비어 있었다. 단추는 섹션마다 있는 [AI 새로 쓰기]·[보완 질문] 사이에 섞여 있었고, 이름 "고르기"는 목록에서
     고르는 일로 읽혀 "넣기"로 보이지 않았다.
  3. 검토 중이거나 마무리된 제안서에서는 섹션 도구가 통째로 숨어 단추 자체가 없었고, ⑥ 제출 전 점검의 "정책 근거 확인 필요"는 초안 보기로만 보냈다.
- ①의 정책 근거 칸은 "선택 입력" 접힌 상자 안에 있었다.

## 선택지
1. 1순위 추천을 정책 근거 칸에 자동으로 넣는다 — 빈칸은 없어지지만 제안자가 보지 않은 문구가 들어간다(ADR 0040 "고른 것만 덧붙임"과 어긋남).
2. 팝업을 자동으로 열고 1순위만 미리 체크해 두되, [적용]을 눌러야 칸에 들어간다. 나중에 다시 넣는 길은 ③·④·⑥ 모두에 둔다.
3. 지금처럼 버튼만 두고 문구만 고친다 — 의견의 원인(넘어가기 쉬움)이 그대로 남는다.

## 결정
2를 택한다.
- ① 네 칸이 상세 입력에 채워지는 순간(간편 입력 [건너뛰고/확인하고 상세 입력에 채우기]) 팝업을 연다. 상세 입력으로 직접 쓴 경우에는 정책 근거가 빈 채
  [다음: 유사과제 확인]을 누를 때 먼저 연다. [적용]·[나중에 넣기] 뒤에는 ② 로 이어 간다. [나중에 넣기]를 한 번 고르면 [다음]에서 다시 묻지 않는다
  (`IdeaState.policyDeferred`).
- 팝업은 열리자마자 `POST /v1/ideas/policy-suggestions` 를 부른다(useAiCall·AiWaiting, 시간 제한 없음). 관련도 1순위(`rank` 1)만 미리 체크하고
  "기본 추천" 배지를 붙인다. 미리 체크는 고른 것이 아니라 **미리 골라 둔 것**이다. 칸에 들어가는 것은 [적용]을 누를 때뿐이고, 체크한 추천과 직접 입력이
  칸 뒤에 덧붙는다(같은 문장은 공백을 무시하고 한 번, `mergePolicyBasis`). ADR 0040 의 "고른 것만 덧붙임·자동 반영 없음"은 그대로 둔다.
- [다시 받기]는 이미 본 문서(`exclude_doc_ids`)를 빼고 더 받는다. 앞서 받은 추천과 체크는 남긴다. 추천 0건·정책 자료 없음(404/405/503)이면
  직접 입력과 [나중에 넣기]만 보인다.
- 정책 근거 칸은 접지 않는다(별도 상자). 칸 아래 [정책 근거 추천 열기]로 언제든 다시 연다. ① 다시 열기(run 안)에도 같은 단추를 둔다.
- 나중에 다시 넣는 길:
  - ③ 정책 근거가 비면 작성안을 처음부터 펼친다.
  - ④ 2-가-(1) 머리에 [정책 근거 넣기·바꾸기]를 늘 보인다. 편집할 수 없을 때도 보이고, 누르면 이유가 나온다. 비어 있으면 주 색으로 칠하고, 본문 자리에
    "정책 근거가 없습니다 — [정책 근거 넣기]" 줄을 둔다. 대화상자에는 ①과 같은 직접 입력 칸을 둔다(줄마다 한 문장, 작성안을 고르면 그 뒤에 덧붙음,
    note "정책 근거 선택" 새 버전, `withManual`). `?policy=1` 로 들어오면 대화상자를 바로 연다.
  - ③ 초안 보기의 빈 2-가-(1) 자리에는 [정책 근거 넣기 (④ 직접 수정)] 바로가기를 둔다.
  - ⑥ 제출 전 점검 "정책 근거" 항목이 확인 필요면 [정책 근거 넣기]를 둔다(→ ④ 대화상자).
- ① 다시 열기(ADR 0035)에서 정책 근거만 바꾸면 이미 2-가-(1)·2-가-(3)이 관련 섹션이었다(`request_change.FIELD_SECTIONS`). 그대로 둔다.
  가짜 모드에서 빈 2-가-(1)이 새 버전에 채워지는 것을 확인했다.
- 서버 변경은 최소로 했다. 추천 응답에 `rank`(1 = 관련도 1순위, 기존 정렬 `rank()` 그대로)를 더하고, 요청에 `exclude_doc_ids`(최대 40,
  `PolicySuggestionsIn`)를 더한다. 자료원 범위와 공용 계정 internal 제외(`PublicOnlyRepository`)는 그대로다.

## 결과
- 화면 접근성: 실제 브라우저 axe(WCAG 2.x A/AA)로 팝업·④ 화면과 대화상자·⑥ 화면 위반 0건(e2e `policy-popup.spec.ts`). 이 점검에서 기존 두 가지도 고쳤다.
  - 문서 칩(DocRef)의 접근 이름이 보이는 글자(제목 · 자료원)와 달랐다 → "제목 · 자료원 근거 보기".
  - 제출 전 점검 항목 단추의 aria-label 에 보이는 글자가 빠져 있었다 → 보이는 글자 + 숨은 "— 이동".
- 기존 e2e 는 [다음] 뒤 팝업에서 [나중에 넣기]를 누르는 도우미(`goPrecheck`)를 거친다.
