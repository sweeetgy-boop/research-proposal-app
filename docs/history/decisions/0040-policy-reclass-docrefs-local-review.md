# ADR 0040 — 자료 분류(연구용역 사내 발주)·문서 표시 공용 도우미·L2 로컬 2차 검토 (2026-10-28 밤, 레인 B)

> 상태(2026-10-29 오후 문서 2차 최신화): 일부 바뀜. ① 정책 근거 추천을 "버튼을 눌렀을 때만" 부르던 방식은 ADR 0052 의 팝업(네 칸이 채워지면 자동 호출, 1순위 미리 체크)으로 바뀌었다.
> "고른 것만 덧붙임·자동 반영 없음"·정책 문서 범위·문서 표시 도우미·L2 로컬 2차 검토는 그대로 유효. 문서 칩 접근 이름은 "제목 · 자료원 근거 보기"로 바뀜.

## 배경
- **정책 근거 추천에 연구용역이 나왔다.** 공사 홈페이지 "정보공개 > 사전정보공표 > 사전정보공개목록" 메뉴 전체를 `doc_type
  policy` 로 적재해, 그 안의 연구용역 목록(infoRelNo 55 — "레인보우 비경열차 관광수요 예측", "고속철도·일반여객 수송수요
  예측" 등 경영연구처·기술연구처 발주 연구 272건)과 행정 공시(채용 친인척 현황·법인카드·소송 판례 …)가 정책 근거 추천과
  정책적 중요도 작성안의 후보가 됐다. 운영 DB 조사: korail_web policy 702건 중 정책·전략 자료는 52건뿐이었다.
- **두 기능의 범위가 달랐다.** ① 정책 근거 추천은 korail_web·molit·rnd_notice 만, `doc_type ∈ {policy, rnd_notice}`, 관련도 하한
  없음. ③ 작성안은 감사원·기재부까지, `audit` 포함, 키워드 0 이면 유사도 0.80 이상.
- **인용 글**에 긴 URL(정책 근거 칸에 넣는 문구가 "…, https://…" 로 끝났다)·앞 글머리("O 이에", "?", "□")가 남았고 300자에서
  "…" 로 잘렸다.
- **화면에 내부 번호**(own:…·alio:sum-…·f:method:t1·s:objective:0)가 근거 패널·인용 목록·검토 의견에 그대로 보였다.
- **로컬 근거 대조(local_check)는 실제로 아무것도 걸러 내지 못했다.** [5]-C 측정은 불일치 0건·섹션 절반 건너뜀(20초 제한).
  심어 둔 틀린 문장으로 다시 재 보니(2026-10-28 22:15, Qwen2.5-7B) 7B 는 `{"support": [...]}` 대신 **배열만** 내서 파서가 전부
  버렸다(판정 0건 → "불일치 0건"). 배열을 받게 해도 바꿔 넣은 수치(3대→10대)를 "지지", 무관한 주장을 "부분" 으로 봤다.

## 결정
1. **자료 분류** (`domain/rules/doc_category`) — 적재(korail_web normalize)와 이주(`rra db reclassify`)가 같은 규칙을 쓴다.
   - 연구용역(사내 발주) = **`doc_type procurement` + `raw.doc_class research_service`**. procurement 는 이미 유사과제 판정에
     "용역" 티어로 들어가고(overlap_exclude 아님) 정책 근거 종류가 아니다. `overlap.yaml candidates.project` 에
     `{source: korail_web, doc_types: [procurement]}` 를 더해 판정·선행연구(5. 특이사항·활용 섹션 근거)에 남긴다.
     화면 구분 이름은 "연구용역(사내 발주)"(`alerts_payload.tier_label`).
   - 행정 공시·사업 현황·규정 = doc_type 은 그대로(policy), `raw.doc_class` 로만 가른다(`admin_record`·`status`). 섹션 근거 구성
     (retrieval_mix)은 바꾸지 않았다 — 통합 담당의 공유 파일이고, 영향은 측정 뒤.
   - 통계자료 게시판(biz_stat_docs) 옛 행 23건은 설정과 같이 `statistics` 로.
   - 키 이름은 `raw.category` 가 아니라 `raw.doc_class` — 국토부(`도로철도 > 철도정책`)·사내 과제(`응용연구`)가 이미 category 를
     다른 뜻으로 쓴다(이주 점검에서 발견).
   - 분류 근거: 사전정보공표 infoRelNo(55 = 연구용역, 경영계획·평가·업무보고·경영목표 등 12개 = 정책), infoRelCategory
     (IRTYP2 경영 / IRTYP6 사업 = 현황 / 그 밖 = 행정), 출처를 모르는 옛 행은 제목(연구·기술개발·실용화·수요 예측·용역).
     다른 메뉴는 메뉴 id 표(현황 15개·행정 9개, 신사업자료실은 검토·자문용역 = 연구용역).
   - `raw.doc_class` 가 없는 옛 행도 `category_of`·`is_policy_basis` 가 그 자리에서 판정한다 — 이주 전에도 범위는 맞다.
2. **정책 근거 범위 하나** — `domain/rules/policy_cards.policy_passage`(정책 문서 `is_policy_basis` + 인용 문장 + 관련도:
   키워드 ≥ 1 또는 유사도 ≥ 0.80)를 ① 추천과 ③ 작성안이 같이 쓴다. 자료원은 둘 다 molit·rnd_notice·korail_web·bai·mofe.
   생성 때 원문 재대조(`verify_sources`)도 같은 판정.
3. **인용 정리** (`policy_phrases.clean_quote`·`pick_quote`) — URL(괄호째) 제거, 앞 글머리·번호·이어 주는 말 떼기, 문장은 통째로만
   (300자 넘는 문장·청크 끝에서 잘린 조각은 고르지 않는다). 원문 대조는 양쪽 다 URL 을 지우고(`match_text`) 본다. 정책 근거 칸에
   넣는 문구에도 URL 을 넣지 않는다(원문 링크는 화면 아래 "원문").
4. **문서 표시 공용 도우미** — 서버 `domain/rules/doc_refs`(자료원 한국어 이름 `SOURCE_NAMES`, `doc_ref`, `replace_internal_ids`)·
   `entrypoints/views_refs`, 화면 `web/src/lib/docRefs.ts`·`web/src/components/DocRef.tsx`. doc_id 를 내보내는 뷰는
   `title`·`source_label`(·공개 문서만 `url`)을 함께 싣고, 화면은 번호 대신 "제목 · 자료원 이름" 을 보이며 누르면 근거 패널(요약 +
   원문 링크). 검토 의견 글 속 번호는 「제목」·"<섹션> 그림 n"·"<섹션> 문장 n" 으로 바꾼다(서버·화면 두 겹). 두 표는 테스트가 맞춘다.
5. **L2 로컬 2차 검토** — `compose.local_check: on`, **시간 상한 제거**(오류 응답만 그 묶음을 건너뜀).
   - 로컬 모델은 "이 문장이 이 근거로 뒷받침되는가?" 만 → 지지/부분/불일치. 판정 기준을 프롬프트에 적고, 배열 응답도 받는다.
   - **규칙이 겹친다**: 근거·제안자 입력·문서 제목 어디에도 없는 수치, 이름이 분명한 것(낫표·따옴표 이름, "제N차 …계획",
     법령명)이 없거나, 한글 근거와 핵심어가 하나도 겹치지 않는 문장은 모델이 너그럽게 봐도 불일치(`local_review.rule_mismatch`,
     state `rule_overrides`). 일정 표기(1~2개월·1년)·문장 속 번호(세부 목표 3:·2차년도)·5. 특이사항(앱 판정을 옮긴 문장)은 규칙에서
     뺀다 — 첫 규칙(grounding 전체)은 실측에서 거짓 불일치 16건("개발계획" 같은 합성어·입력의 "10편성")을 냈다.
   - 순서: 2-가-(1)·2-가-(2) 섹션과 수치·연도·고유명 문장 먼저, 나머지 뒤(`check_batches`).
   - 불일치 문장만 Argon(argon_first — 오류 응답일 때만 로컬)에 근거와 함께 보내 "근거 안에서 다시 쓰기 또는 빼기" 제안.
     다시 쓴 문장이 근거 밖 이름·수치를 담으면 "빼기" 제안으로 바꾼다. 공용 계정 run 은 사내 전용 근거를 보내지 않는다.
   - **자동 반영 없음**: [반영] = 보통 편집 경로(`apply_edits`, 다시 쓰기는 직접 수정·원래 근거 유지, 빼기는 삭제) → 새 버전.
     [무시] = 결정 기록만(`state.local_check.suggestions[].status=dismissed` + `proposer_notes.json local_review_decisions` +
     레인 D 확인 기록 `record_mark("suggestion_ignore")`), **새 버전 없음**. 결정한 문장은 알림·제출 전 점검에서 빠진다.
   - 제출 전 점검 "근거 확인" 에 결정 전 로컬 불일치 수(`local_mismatch`), manifest `local_check.counts`(지지/부분/불일치·제안 수·
     상태별·초).

## 결과
- 운영 DB 이주(백업 `data/backups/rra-20261028-214727.sqlite` 뒤): korail_web 702건 바뀜 — 연구용역 287(사전정보공표 272 +
  신사업자료실 15)·행정 공시 270·사업 현황 70·통계 23·정책 52. 정책 근거 후보 702 → 52. 다른 자료원(molit 6·bai 21·mofe 10·
  rnd_notice 91·own·alio·datago·실시간 검색 행)은 0건 바뀜. 재색인 없음(본문·청크 그대로). 자세히 `docs/eval-2026-10-28-policy-reclass.md`.
- 로컬 검사기: 심은 틀린 문장 6개 중 수치 바꿈 2/2 불일치(규칙), 무관 주장 1/1 불일치(규칙), 맞는 수치 문장 1건을 7B 가 불일치로 봄.
- 실측(골든셋 01·02·03, 단독·동시 3건, 그림 끔): L2 가 더하는 시간은 로컬 판정 20~46초 + 불일치가 있을 때 Argon 제안 5~18초
  (동시 4건). 7B 스스로의 "불일치" 는 0건 — 불일치는 규칙이 잡는다. 최종 규칙을 측정 run 문장 122개에 다시 적용하면 거짓 불일치 0건,
  최종 규칙 실측(02)은 24문장 중 1건(근거에 없는 성과지표 기간)이며 Argon 이 근거 안에서 다시 쓰기를 제안했다.
- 정책 근거 추천(골든셋 4건): 전 19건 중 16건이 연구용역·행정 자료 → 후 연구용역 0건(국토부·감사원·공사 경영 자료만).
- 한계: 행정 공시·현황도 policy 라 2-가-(3) 전략 정합성 근거에는 남을 수 있다(retrieval_mix 는 통합 담당 몫). 7B 판정은 거짓
  불일치가 있다 — 그래서 자동 반영 없이 제안자가 고른다.
