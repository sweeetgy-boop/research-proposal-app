# ADR 0041 — 그림 모양: 가로로 넓게·본문 폭에 꽉·글자 9pt 이상 (2026-10-28 밤, 레인 C, 항목 23)

## 배경
시범 의견: 그림이 세로로 길거나(SWOT 2×2 = 4:3, 112mm) 본문 폭보다 좁게(148mm 고정) 들어가고, 넣고 나면 그림 안 글자가 본문(12pt)보다
훨씬 작다. 실측: 실물 양식(별지 제2호서식) 본문 안쪽 폭은 153.8mm(쪽 59528 − 좌우 여백 7086×2 − 본문 단락 오른쪽 여백 1750 HWPUNIT),
이 폭에 1600 단위 밑그림을 넣으면 글자 1단위 ≈ 0.27pt — 예전 상자 글자 30 = 8.2pt, 눈금·안내문 20 = 5.4pt, 글자 하한 11 = 3pt.

## 결정
1. **가로 비율만** (`domain/rules/figure_fit.WIDE_ASPECTS`): As-Is/To-Be·분석 기법·개념도·체계도·그래프·비교표 16:9 또는 21:9, 추진 일정표·
   로드맵 21:9 또는 4:1. 내용 양으로 고른다(`choose_aspect`) — 짧으면 21:9, 칸이 많으면 16:9, 일정 4단계 이하·이름 12자 이하면 4:1.
   예전 고정 비율(4:3·3:2)은 그 종류의 가로 비율로 올린다(`wide_aspect`).
2. **4:1** 은 Nano Banana(imageConfig.aspectRatio)가 받지 않는다 → 21:9 로 생성. 밑그림을 21:9 흰 캔버스 가운데에 넣어 보내고(`pad_to_aspect`),
   프롬프트에 "캔버스 가운데 4:1 띠 안에만" 을 적고, 결과의 흰 여백을 잘라 맞춘다(`fit_aspect`). 모든 생성 그림은 흰 여백을 자른 뒤
   목표보다 넓으면 위아래만 채우고, 그 종류의 가장 덜 넓은 비율보다 좁으면 좌우를 채우고, 그 사이면 그대로 둔다(좌우 여백을 늘리지 않는다).
   그래서 실제 비율은 "2.62:1" 처럼 고른 값과 다를 수 있고, 맞춤 기록은 실제 픽셀로 적는다.
3. **가로 배치** — 프롬프트 "가로로 넓게 배치, 좌우 여백 최소: 묶음·상자는 왼쪽에서 오른쪽으로 나란히, 세로로 쌓지 않는다". 배치는
   `techniques.yaml arrange`: row(SWOT·TOWS·PMI·시나리오 = 한 줄), split(비용-편익·비용-효과·역장분석 = 좌우 두 단), flow(델파이·문헌고찰·
   의사결정나무·LCC·민감도·DEA = 한 줄 + 화살표), grid(PEST(EL)·6색 모자, 묶음 5개 이상 = 가로 두 줄), table(비교·평가 = 열이 대안인 표).
   As-Is/To-Be 는 왼쪽·오른쪽 두 단 + 가운데 화살표. 밑그림(SVG)도 같은 배치로 그린다.
4. **HWPX 폭 = 본문 안쪽 폭** — `adapters/rendering/hwpx_geometry` 가 렌더 결과에서 그림 표식 단락의 자리 폭을 읽는다(쪽 폭 − 좌우 여백 −
   단락 오른쪽 여백, 표 칸이면 칸 폭 − 칸 여백 − 단락 여백). 그림 단락은 서식 점검(hwpx_format)이 왼쪽 0·들여쓰기 0·가운데로 바꾸므로
   왼쪽 여백은 빼지 않는다. 높이는 픽셀 비율, **상한 = 쪽 높이 × 1/3**(99.0mm). 넘으면 그림 단계가 더 넓은 비율로 다시 그린다
   (`fit_aspect_for_frame`); HWPX 에서 넘는 것은 예전 그림뿐 — 높이에 맞춰 줄이고 `fits=false`.
5. **글자 크기 ≥ 9pt**(`figures.yaml fit.min_text_pt`). 밑그림: 본문 폭에서 9pt 가 되는 단위(33.1)를 글자 하한으로(`min_font`), 본문 37(10pt)·
   머리글 42~46. 하한으로도 칸에 안 들어가면 SVG 에 `data-overflow` 를 세고, 그림 단계가 ① 같은 종류의 덜 넓은 가로 비율을 한 번 → ② 글자 줄이기
   (`shorten_spec`: 띄어쓰기 자리에서 22자·묶음당 항목 3 → 16자·항목 2, 일정 단계 이름 14→10자; 수치 그래프·기간은 건드리지 않음;
   줄인 글자는 원래 글자의 앞부분이라 출처 검사를 그대로 통과) 순서로 다시 그린다. 제안자가 [글자 고치기]로 쓴 글자는 줄이지 않고 기록만.
6. **Nano Banana 그림의 글자 크기 어림** = OCR(macOS Vision, `adapters/vision/ocr_mac`, 격리 자식) 상대 비교: 밑그림과 생성 그림을 둘 다 OCR 해
   같은 글자의 줄 상자 높이(mm 로 환산) 비를 그 글자의 밑그림 크기(SVG font-size → pt)에 곱하고, 가장 작은 값을 쓴다(`estimate_relative_pt`).
   OCR 상자 높이 ÷ 글자 크기 비는 글자 모양마다 다르다(한글 두 글자 0.95, 괄호가 든 줄 1.2 — 밑그림 보정 16줄 1.13~1.44) — 같은 글자끼리
   나누면 지워진다. 함께 찾은 글자가 없으면 그림만으로 상자 높이 ÷ `ocr_box_em`(1.2). OCR 이 없으면(리눅스·CI) 밑그림 값. 9pt 미만이면 한 번 더
   (`max_image_redraws` 1, 그림 호출 +1): 줄일 글자가 있으면 줄여 밑그림부터, 없으면 프롬프트에 "글자를 더 크게: 직전 그림은 약 n pt" 를 붙인다.
7. **기록** — `Figure.fit`(FigureFit: width_mm·height_mm·ratio·fits·min_text_pt·text_ok·text_method svg|ocr|baseline·redraws·shortened·widened),
   HWPX 삽입 결과 `FigurePlacement.fit`(넣은 실제 폭으로 글자 pt 를 다시 계산), manifest `figures[].figure_fit`(숫자·코드만, 허용 키 검사).
   통합 점검 "그림이 본문 폭에 맞게 들어감 n/n" = `figure_fit.fits` 이고 `width_mm` 이 본문 폭.
8. **카드·이름** — 카드는 그림을 `fit.aspect_css` 비율로 카드 폭에 꽉(높이 제한 없음), 아래 한 줄 "본문 폭 153.8mm × 높이 65.9mm · 가장 작은 글자
   약 9.3pt". 이름은 한국어 `display_name`(API 필드 + `Figure.display_name` 속성): "현재·연구 후 비교 그림", "분석 기법 그림 – SWOT 분석", 그 밖
   종류 이름. 기법 이름의 영어 병기(퓨 매트릭스(Pugh)·역장분석(Force Field))는 뺐다. 오류 코드 대신 `error_label`(한국어 한 줄). 새 그림의
   캡션 기본값도 한국어 이름. 수치 그래프 출처는 그림 안에 그리지 않는다(HWPX 캡션 아래 12pt 출처 줄이 맡는다).
9. AI 를 부르는 그림 동작([다시 만들기]·[말로 고치기]·[다른 기법으로 바꾸기]·[다른 그림 추가]·기법 [다시 시도])은 시간 제한 없이 "응답 기다리는 중 ·
   경과 n초" + [취소](ADR 0038) — REST 3경로 `cancel_on_disconnect`(499, 새 버전 없음).

## 쪽 미리보기
한/글이 설치된 맥에서는 한/글 Quick Look 확장(`HwpQLExtViewAsThumbnails`)이 HWPX 첫 쪽을 실제로 그린다 — Swift `QLThumbnailGenerator`
(도구 `tools/eval_figures_wide.py --thumb`). 첫 쪽만 되므로 그림마다 그 그림이 1쪽 2-가-(1) 에 오는 미리보기용 HWPX 를 만들었다(같은 본문 단락
모양이라 크기는 같다). AppleScript 사전·PDF 내보내기 CLI 는 없다.

## 결과
- 측정 `docs/eval-2026-10-28-figures-wide.md`, 샘플 `docs/history/screens/2026-10-28-figures-wide-*`: 실물 양식 9/9 본문 폭·높이 상한 안, 글자 9pt 이상
  8/9(밑그림 9/9), 다시 그림 2/9, 이미지 32회.
- 실측 중 바꾼 것: OCR 절대 어림(밑그림에서도 6~8pt 로 낮게 나옴) → 상대 어림, 흰 여백 맞춤이 좌우를 채워 폭을 줄이던 것 → 사이 비율은 그대로,
  그림 글자가 작을 때 글자 줄이기 → 내용은 두고 "글자를 더 크게"(작은 것은 이름표 꼬리표였다).

## 후속
- OCR 어림은 OCR 이 같은 글자를 두 그림에서 찾을 때만 상대값이다. 그림이 글자를 바꿔 쓰면(ADR 0033 후속) 그 글자는 빠진다.
- 줄일 글자도 없고 "글자를 더 크게" 1회 뒤에도 작으면 그대로 넣고 카드·manifest 에 `text_ok=false` 로 남긴다(제출 전 점검 연결은 후속).
- 분석 기법 묶음 이름의 영어(Plus(장점) 등)는 그림 안 글자라 기존 명세 검사와 묶여 있어 그대로 두었다.
