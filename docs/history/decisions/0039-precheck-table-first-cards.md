# ADR 0039 (레인 A) — ② 표 먼저·선택 적용·카드 겹침 재판정 (2026-10-28 밤)

## 배경
시범 ② 는 36~76초 걸렸다. AI 같음 판정(Argon)과 자동 과제안이 끝나야 표가 보였고, 판정은 40초(로컬 60초)를 넘으면
규칙으로 바뀌었다. 행을 누를 때마다 비교표가 다시 만들어져 기다림이 잦았고, 표의 "유사도 0.86"(모든 행 0.85~0.86)은
뜻이 없었다. 차별화 과제안 카드의 "근거 과제·자료" 는 내부 번호(own:…·alio:sum-…)였고, "기존 과제 n건과 가깝다" 경고는
카드 글의 e5 재검색이라 거의 모든 카드에 붙었다.

## 결정
1. **표 먼저.** `POST /v1/precheck?stage=rule` 은 실시간 검색 + 규칙 판정(reranker ≥ 0.5 + 핵심 키워드)까지만 돌려주고
   (`judgment.status = pending`) 규칙 판정을 입력 해시 메모에 "판정 전" 으로 남긴다. 화면은 바로 이어서
   `POST /v1/precheck/judgment`(AI 판정)와 `POST /v1/precheck/recommendations`(과제안)를 함께 부른다. 서버는 같은 입력의
   판정을 **한 작업으로 공유**한다(`PrecheckOverlap.judgment/current/_join`) — 과제안 요청이 먼저 와도 판정은 한 번이고,
   과제안은 AI 판정을 기다려 근거로 쓴다(AI "다르다" 이고 고르지 않은 행은 빼고). 기다리는 요청이 모두 끊기면(화면 [취소])
   작업도 취소된다. `stage=full`(기본 — MCP·run 화면)은 종전대로. 응답을 나눈 이유: 판정 전용 경로가 이미 있고([다시 시도]),
   스트리밍(SSE) 없이도 화면이 두 요청으로 단계별로 채울 수 있다.
2. **제한 시간 없음.** 판정(`judge_sameness`)·다듬기(`polish_field`)·비교표 원문 추출(`extract_cells`)의 `asyncio.wait_for`
   와 `overlap.yaml judgment.timeout_seconds·local_timeout_seconds` 를 없앴다. 느린 Argon 은 오류가 아니다 — 로컬 → 규칙
   대체는 오류 응답(예외·예산·해석 실패)일 때만. 화면은 "응답 기다리는 중 · 경과 n초 [취소]"(공용 `useAiCall`·`AiWaiting`),
   서버는 ② AI 경로 전부를 `cancel_on_disconnect` 로 감싼다(판정·과제안·더 만들기·활용 제안·비교표·다듬기).
3. **판정 칸.** 같다 → 차단, 일부 겹침 → 근접, 다르다 → 관련 낮음(`domain/rules/precheck_levels`). AI 판정 전·실패면
   규칙 판정(차단·근접)을 "규칙 기준" 으로 보인다.
4. **관련도 한 칸.** reranker 점수를 쉬운 말로 — 높음(≥ 0.8)·보통(≥ 0.5, 규칙 차단 하한)·낮음. e5 유사도 숫자는 ② 화면
   어디에도 보이지 않는다(표·관련 연구·NTIS 카드). 판단: 숫자 대신 말로 — 0.5 는 v2 측정에서 정답을 모두 지키는 하한, 0.8 은
   정답 9건 중 8건이 넘은 값.
5. **기본 선택.** AI "다르다" 행만 [관련 없음] 을 미리 고른다(`default_choices`, 화면은 선택이 없는 행에만). 일부 겹침·같다는
   비워 제안자가 정한다. 차단 행 게이트는 그대로.
6. **선택 적용.** 행 선택은 더는 바로 반영되지 않는다. 화면 아래 붙은 막대(`SummaryBar`, `bottom: var(--stepnav-h, 0px)`)의
   [선택 적용] 이 비교표·활용 제안·(바뀌었으면) 과제안을 그 선택으로 다시 만든다. 선택이 바뀌면 버튼이 켜지고 "이전 선택 기준"
   안내, 적용 뒤 "선택 적용됨 · 비교표 갱신".
7. **카드 겹침 재판정.** 카드 글(가제·요약·목표·방법·범위 — 기존 과제를 말하는 차별점 문장은 뺌)로 ② 규칙 판정(같은 reranker·
   아이디어 핵심어)을 돌려 걸린 과제(카드마다 최대 3)를 Argon **한 번에** 같음 판정(`usecases/card_overlap`). "같다" 카드는
   보이기 전에 그 카드만 한 번 다시 받는다(겹친 과제 제목·겹치는 점을 피하라는 지시). 그래도 겹치면 경고에 가까운 과제 1~2건
   제목 + 판정의 한 줄 겹치는 점(판정이 이유를 안 주면 제목만). AI 확인 실패면 규칙에 걸린 과제를 "규칙 기준" 경고로, 다시
   받지 않는다. 끄기: `overlap.yaml judgment.cards: false`(종전 자기 중복 검사).
8. **차별성 정렬.** 가까움 = 판정 후보마다 reranker 점수 + 판정 가중치(같다 1·일부 겹침 0.5·다르다 0·규칙 기준 0.5)의 최댓값,
   후보가 없으면 카드 글 검색 최고 점수 × 0.5. 낮은 순(가장 다른 안 먼저). 차별성 판단 높음/보통/낮음은 "판단" 으로 표시.
9. **더 만들기.** `POST /v1/precheck/recommendations/more {request, rec_id}` — 세션의 카드를 "[이미 보인 과제안]" 으로 주고 다른
   안만 받는다. 같은 검증·겹침 재판정, 이미 보인 안과 거의 같은 안(토큰 자카드 ≥ 0.8)은 제외. 같은 세션 id 에 이어 붙어 번호가
   이어진다(최대 15, apply 의 index 상한 14). 새 안은 뒤에 붙는다(앞 카드 번호를 바꾸지 않으려고 전체를 다시 정렬하지 않는다).
10. **내부 번호 없음.** 카드 근거는 `refs[{title, source_label}]`(상위 3 + [더 보기]), 표 행은 자료원 이름. 표·관련 연구·NTIS
    카드에서 doc_id 표시를 뺐다.
11. **일반어.** 시범 실시간 검색 Argon 키워드 30건·시범 run 알림 키워드에서 여러 분야에 두루 나온 37개(예측·변화·수요·추정·
    산정·운행·차량 …)를 `generic_terms` 에 더했다. 겹친 핵심 키워드 칸은 아이디어 핵심어와 겹친 낱말만(종전 규칙 그대로).

## 결과
측정은 docs/eval-2026-10-28-precheck-v3.md. 표는 실시간 검색 대기 + 규칙 판정 시간에 보이고, AI 판정·카드는 뒤에서 채워진다.

## 한계
- 과제안은 판정을 기다리므로 첫 카드까지 = 판정 + 과제안 + 카드 확인(+ 다시 받기). 표가 먼저 보이므로 체감 대기는 줄지만 총
  시간은 v2 와 비슷하거나 길다(카드 확인 1회 + 다시 받기).
- 가짜 모드 저장소는 reranker 점수를 내지 않아 e2e 는 카드 다시 받기 경로를 지나지 않는다(유스케이스 테스트로 확인).
- 판정 공유 작업은 프로세스 메모리다(재기동하면 다시 판정).
