# ADR 0049 — 연구 작업실 홈과 제안서 진행률(6단계) 표시 (2026-10-29, [UI] 레인 2, #104)

## 맥락
웹 첫 화면이 ① 입력이라 만든 제안서와 진행 상황을 한눈에 볼 곳이 없었다. 동료 UI("Research Studio")는 홈에 건수·최근 제안서·진행률을 보인다.
로그인 전에도 같은 화면 틀을 보여 달라는 요구가 있었다(개인 데이터 없이).

## 결정
- `/` 를 연구 작업실 홈으로 둔다.
  - 로그인 전: 히어로·시작 안내·로그인 카드만 보인다. `/v1/...` 호출은 0건이다.
  - 로그인 뒤: run 목록 API 하나로 다음을 만든다.
    - "연구 한눈에 보기"(전체·작성 중·마무리 완료)
    - 최근 제안서 표(탭·검색·정렬·진행률)
    - [이어서 작성하기]
- 진행률은 섹션 진행이 아니라 **6단계 중 끝난 단계**로 센다(생성 중 33% … 마무리 100%).
- 상태 칩은 작성 중·검토 중·마무리 완료 세 가지로 맞춘다. 멈춤·실패는 칩 글자를 상태 이름으로 보인다. 계산은 순수 함수 `features/home/runView.ts`.
- 과제유형은 run 응답 `task_type` 으로 보탠다(확정값이 우선, 없으면 초안 1-다 제안값).
- 작성 가이드(`/guide`)는 `docs/pilot-guide.md` §2~§5.5 의 사용자용 부분을 정적 화면으로 옮긴 것이다(`features/guide/content.tsx`).

## 결과
- 새 API 는 없고 필드 하나만 늘었다. 로그인 전 요청은 0건이다.
- 안내서와 화면 글이 두 곳에 있으므로, 안내서를 고치면 `features/guide/content.tsx` 도 함께 고친다.
- 건수는 목록 API 상한(50건) 안에서 센다.
- 근거: `docs/status.d/feat-ui-studio-home.md`.
