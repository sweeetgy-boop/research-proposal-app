# ADR 0057 — ② 과제안 두 갈래: 유사과제가 없으면 '새 과제 추천'(장벽 해소형 과제명) (2026-11-05, feat/novel-recommend)

## 맥락
- ② 과제안은 '차별화' 틀 하나였다(ADR 0012·0039). ADR 0053 은 [유사함] 0건이면 `recommend.md` 가 '새 영역' 1~3건을
  내게 했지만, 비교할 기존 과제가 없는 아이디어에 "무엇과 다른가"를 묻는 구조라 안이 엉성했다.
- 운영에서 "철도역사 비둘기 침입 방지" 아이디어가 유사함 0건으로 확인됐다. 이런 아이디어에 필요한 것은 차별점이 아니라
  ① 정말 새로운지(확인 범위), ② 다른 분야는 같은 문제를 어떻게 풀었는지, ③ 왜 아직 아무도 안 했는지(장벽)다.

## 선택지
1. 그대로 둔다 — `recommend.md` '새 영역' 지시만 손본다. 비교 대상이 없는 구조 문제는 남는다.
2. 화면에서만 문구를 바꾼다. 안의 내용은 같다.
3. **갈래를 나눈다.** [유사함] 0건이고 차단도 없으면 `novel` 갈래로 넓은 새로움 확인 → 유추 검색 → 장벽 점검 →
   장벽 해소형 과제명을 낸다. 나머지는 종전 차별화 그대로.

## 결정
3을 택한다.
- **판정 한 곳** `application/usecases/similar_rows.recommend_mode` — `novel` = `similar_rows` 0 AND `effective_blocking` 거짓.
- **새로움 확인** novel 이면 실시간 검색 범위를 넓혀 한 번 더 보고, 유사 과제가 새로 걸리면 novel 을 취소하고 차별화로 되돌린다
  (그 행은 ② 표에 더함). 확인 범위(coverage)에는 실제로 확인한 자료원만 쓴다.
- **유추 검색** 아이디어에서 대상·장소 단어를 빼고 '문제' 축만 남긴 질의로 철도 밖 분야 사례 최대 5건(관련도 하한 0.79 그대로).
  분야 이름은 자료원 메타데이터에서만 가져온다.
- **장벽 해소형 과제명** 안 2~3건마다 장벽 5갈래(수요·규제·비용·기술·운영)를 점검하고, 해소 전략이 드러나는 과제명 1~3개와
  이유를 낸다. 장벽 근거는 자료에 있으면 '근거 있음'+doc id, 없으면 '추정'+확인 방법. 법령명·조항·수치·기관명을 지어내면 폐기.
- **호환** differentiate 응답·동작은 그대로다. 응답에 `mode` 만 더한다. 요청 몸통은 바뀌지 않는다.
- 계약: `docs/contracts/novel-recommend.md`.

## 결과
- 좋은 점: 유사과제가 없는 아이디어도 "어떻게 과제가 되게 할까"에 답하는 안을 받는다. '추정' 장벽은 확인 방법이 붙어 사람이 판단한다.
- 비용: novel 갈래는 실시간 검색 1회(넓힘)·유추 검색 1회가 더 들어 과제안이 늦어진다. 같은 입력은 세션 안에서 재사용한다.
- 남은 것: 장벽 '근거 있음' 비율·과제명 채택률은 시범 사례가 쌓인 뒤 측정 줄(`branch`·`barriers`·`titles`)로 본다.
