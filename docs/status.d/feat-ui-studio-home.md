## ADR 초안 (레인 5 가 0048 이상 번호로)
- 제목: 연구 작업실 홈과 제안서 진행률(6단계) 표시
- 맥락: 웹 첫 화면이 ① 입력이라 만든 제안서·진행 상황을 한눈에 볼 곳이 없었다. 동료 UI("Research Studio")는 홈에 건수·최근 제안서·
  진행률을 보인다. 로그인 전에도 같은 화면 틀을 보여 달라는 요구(개인 데이터 없이)가 있다.
- 결정: `/` 를 연구 작업실 홈으로 두고, 로그인 전에는 히어로·시작 안내·로그인 카드만, 로그인 뒤에는 run 목록 API 하나로 건수·표·
  [이어서 작성하기]를 만든다. 진행률은 섹션 진행이 아니라 6단계 중 끝난 단계로, 상태 칩은 작성 중·검토 중·마무리 완료 세 가지로
  매핑한다(`features/home/runView.ts`, 순수 함수). 과제유형은 run 응답 `task_type`(확정값 > 초안 제안값)으로 더한다.
  작성 가이드는 시범 안내서 사용자용 부분의 정적 화면이다(안내서가 바뀌면 `features/guide/content.tsx` 도 함께 고친다).
- 결과: 새 API 없음(필드 하나 추가). 로그인 전 요청 0건. 안내서와 화면 글이 두 곳이라 개정 때 함께 고쳐야 한다. 건수는 목록 API 상한(50) 안에서 센다.
