# ② 유사과제 고도화 1단계 측정 — 스위치 off / facets on / idf on (2026-11-09, 레인 E, ADR 0059·0064)

## 1. 방법
- 골든셋 12건: `tests/golden/*.yaml` 10 + `not_similar/` 2. 도구 `tools/eval_overlap_facets.py` — `build_precheck` 유스케이스 직접 호출
  (`rule_stage`, REST 아님), 원 저장소 `data/rra.sqlite`(읽기만, 16,431 문서·36,711 청크), e5 임베딩 + reranker(`bge-reranker-v2-m3`, MPS).
  **LLM 호출 0회** — 같음 판정은 규칙 판정까지만, 4축 분해는 규칙 사전만(로컬 모델 없음), 핵심어는 아이디어 제목(Argon 키워드 대신).
  `tools/with_heavy_lock.py` 안에서, 모드마다 사례 2회 중 최소 시간.
- 적중 = 정답(`expected_similar`)이 행 상위 5(doc_id·merged_ids) 안 (03 은 차단 0), 거짓 차단 = `must_not_block`·03 의 규칙 차단.
  모드: **off** = 세 스위치 false(= 지금 운영), **facets** = `facets.enabled` 만 true(규칙 분해 → 축별 `find_similar` → RRF k=60),
  **idf** = `idf_weighting.enabled` 만 true(`rra db idf` 캐시, 토큰 200,000, max_idf 9.71, `min_weight_ratio` 1.0).
- 이 측정은 스위치를 켜도 되는지의 **최종 근거가 아니다**(규칙 판정·규칙 분해만). 켜기 결정은 L1 비교(연습용 묶음, 메인 2차)에서.

## 3. 읽기
- **off(지금 운영) 11/12** — not_similar/01 의 정답(「영업정지역의 역사·문화자원 활용방안」)이 7위. 규칙 차단 6행이 앞에 서서 밀린 것이고,
  운영에서는 Argon 같음 판정이 그 6행을 "다르다" 로 바꿔 상위에 올린다(v3 측정 ○). 규칙만 보는 이 측정의 한계.
- **facets on 10/12, 중앙 +0.43s** — 01 은 1위로 올랐지만(축 질의 "궤도"·"센서 감지" 가 사내 기록을 앞세움) **10 분산에너지의 정답 alio 요약이
  풀에서 빠졌다**: 규칙 분해가 "유휴" 를 problem 으로, 나머지를 전부 target 한 축에 몰아 두 질의가 됐고 RRF 가 홈페이지·사내 문서를 앞세웠다.
  규칙 분해만으로는 켤 근거가 없다 — 로컬 모델 분해로 다시 재야 한다(이번에는 mlx 를 부르지 않았다). 지연은 축 질의 수(2~4)만큼 임베딩·검색이 늘어
  +0.3~0.7s.
- **idf on 12/12, 규칙 차단 행 60 → 35** — 흔한 낱말 한 개(역사·공간·감지 …) 겹침으로 규칙 차단되던 행이 빠지고(01: 10→3, not_similar/01: 6→0),
  차단 먼저 정렬이라 정답이 2위로 올라왔다. 정답을 잃은 사례는 없고 거짓 차단 0. 가중 합 조건은 "핵심어 중 가장 흔한 것 하나만 겹친 문서" 를
  걸러 내는 효과다. `min_weight_ratio` 1.0(계약 그대로) 유지 — 더 올리면 05·08 처럼 정답이 여러 흔한 낱말로만 겹치는 사례가 위험하다.
  단, 규칙 차단이 줄면 Argon 판정에 보내는 상위 10 의 구성이 달라지므로 AI 판정 포함 L1 비교로 확인해야 한다.

## 4. 결정·다음
- 세 스위치 모두 **off 로 배포**(ADR 0059). `idf_weighting` 이 가장 유망(적중 유지·규칙 차단 42% 감소). `facets` 는 로컬 모델 분해 측정 뒤.
