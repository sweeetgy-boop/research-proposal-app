# 시연 대본 (웹 화면, 약 8분)

준비: `cd /Users/chan/projects/research-proposal-app && .venv/bin/rra api --port 8000`(127.0.0.1:8000, `web/dist` 서빙) 와 mlx 서버(Qwen, 127.0.0.1:8080)가 떠 있고 `.env` 에 Gemini 키가 있다. 시연용 아이디어는
골든셋 01(궤도 틀림 상시 감지). 실패 대비: `docs/history/demo/` 의 녹화를 바로 틀 수 있게 열어 둔다.
Gemini 가 안 되면 ③ 은 v1 까지, ⑤ 는 "건너뜀(review_skipped)" 으로 ⑥ 까지 간다 — 이것도 설계된 경로라고 말한다.

| 단계 | 보여 줄 것 | 말할 것 |
|---|---|---|
| 0 로그인 | 토큰 한 번 입력 → 세션 쿠키 | 토큰은 저장하지 않는다. 127.0.0.1 만 듣는다 |
| ① 간편 입력 | 아이디어 한두 문장 + 가제 → [네 칸으로 나누기] → 네 칸 미리보기·보완 질문 2~4개 → 답 반영 → 상세 입력에 채우기 | 로컬 모델이 나누되 문장에 없는 내용은 빈칸으로 두고 묻는다. "상세 입력(4칸)" 으로 바로 쓸 수도 있다 |
| ① 정책 근거 추천 | [추천 받기] → 공사 정책 문서 문구 3~5개(문서·연도·쪽·원문·링크) → 하나 고르면 정책 근거 칸 뒤에 덧붙음 | 자동으로 넣지 않는다. 정책적 중요도는 제안자가 적은 근거만 쓴다 |
| ② 유사과제·추천·비교표 | 알림 표(구분·유사도·겹친 키워드), 차단이면 확인 체크, 추천 카드, 차별성 비교표(제안 과제 + 상위 5 × 5 관점) | 유사도 AND 공유 키워드 + reranker. 최종 판단은 사람. 서버도 확인 없이는 생성을 막는다(409) |
| 브리핑 | 선행연구 10건 한 줄 요약·연도 막대·주제어·연구 공백 후보 → 논문 체크 | 고른 논문은 섹션별 검색의 우선 근거. 건너뛸 수 있다 |
| ③ 생성 진행 | 스테퍼, 단계 목록(근거 찾기 → 섹션별 검색 → 섹션 12 → 규칙 검사 → Argon 1차 검토·보완) | 섹션마다 로컬 모델 1회, 근거 id 는 검색 집합과 대조. Argon 은 수정안·추가 문장·근거 지지 여부를 한 번에 |
| 초안·근거 패널 | 문장 클릭 → 근거 발췌·자료원·기관·연도·수집일·근거 수준(원문/공개 요약/초록/이미지 판독)·지지/부분/불일치 → 승인/교체/제외 | 요약·제목·이미지 기반은 "세부 확인 필요". 판단은 버전에 남는다 |
| ④ 섹션 다시 쓰기·보완 질문 | [AI 다시 쓰기] 현재/후보 나란히 → 고른 것만 반영 / [보완 질문] 빠진 요소 답 저장 | 제안자가 고친 문장은 보존, 선택값은 바꾸지 않는다 |
| ⑤ 최종 검토 | 요청 → 점수·1차 대비 변화. 더 고치면 "최종 검토 이후 수정 n건" | 1회 기본, 다시 받기는 선택(ADR 0011) |
| 제출 전 점검 | 9항목(필수 섹션·미해결 알림·근거 승인률·메모·수정·확정·칸 길이·전략체계 초안·검토 상태) → 항목 클릭으로 이동 | 전략체계가 초안이면 여기서 보인다 |
| ⑥ 최종 마무리 | 선택형 확정, 제안자 정보(저장 안 됨), 점검, HWPX 다운로드, 만족도 1~5 | 양식 파일은 이 경로로만. 만족도·사용 기록은 개인정보 없이 usage.json |
| 부록 | run 목록·자료 검색·자료원 상태("공사 홈페이지 자료: 2026-10-27 기준 스냅샷"), manifest | 무엇을 외부에 보냈는지 항상 남는다 |

말하지 않을 것: 사내 과제명·개인 이름. 화면에 뜨는 사내 자료 제목은 공시된 것만 쓴다.
