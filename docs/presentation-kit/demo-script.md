# 시연 대본 (웹 화면, 약 8분)

준비: `rra api`(127.0.0.1:8000, `web/dist` 서빙) 와 mlx 서버가 떠 있고 `.env` 에 Gemini 키가 있다. 시연용 아이디어는
골든셋 01(궤도 틀림 상시 감지). 실패 대비: `docs/history/demo/` 의 녹화를 바로 틀 수 있게 열어 둔다.
Gemini 가 안 되면 ③ 은 v1 까지, ⑤ 는 "건너뜀(review_skipped)" 으로 ⑥ 까지 간다 — 이것도 설계된 경로라고 말한다.

| 단계 | 보여 줄 것 | 말할 것 |
|---|---|---|
| 0 로그인 | 토큰 한 번 입력 → 세션 쿠키 | 토큰은 저장하지 않는다. 127.0.0.1 만 듣는다 |
| ① 아이디어 입력 | 필수 4칸(현황·원인·한계·목표) + 가제·제약·정책 근거 | 필수 규칙은 도메인 모델 한 곳(validator). 성명·연락처는 받지 않는다 |
| ② 유사과제 확인 | 알림 표(구분·유사도·겹친 키워드·상태), 차단이면 확인 체크 | 유사도만으로는 한국어 문서가 전부 0.80 을 넘는다 → 공유 키워드 조건(ADR 0004). 최종 판단은 사람 |
| ② 과제 추천 | 추천 카드 0~5건, "이 방향으로 진행" 미리보기 → 확정 / 원래 아이디어로 | 기존 과제와 차별성 있는 과제를 이유·근거 id 와 함께. 검증(수치·정책명·중복) 통과분만 |
| ③ 보강 질문 | 질문 최대 3개, 답 또는 건너뛰기 | 답은 "보충 정보" 로 설계도·작성에 들어간다 (pipeline.clarify) |
| ③ 생성 진행 | 스테퍼 ①~⑥, 단계 목록(근거 찾기 → 설계도 → 섹션 12 → 규칙 검사 → Argon 1차 검토) | 섹션마다 로컬 모델 1회, 근거 id 는 검색 집합과 대조해 밖이면 폐기. 중단돼도 섹션 단위로 재개 |
| ③ 초안 v2 | 문장마다 근거·출처 배지(로컬 작성/Argon 보완/Argon 추가), 경고(수치·긴 문장), 1차 검토 패널(점수 4개·의견·후보 선택 "다른 후보 보기") | Argon 은 새 사실을 못 넣는다 — 수정안·추가 문장도 근거 범위·수치·정책명 검증을 거친다. 선택값은 바꾸지 않는다 |
| ④ 직접 수정 | 문장 하나 "수정안 사용", 하나 직접 수정, 메모 저장 → v3. 버전 비교(글자 단위 diff), 복원 | 외부 LLM 없음. 같은 내용이면 버전 없음. 두 창에서 동시에 저장하면 409 |
| ⑤ 최종 검토 | 요청 → 점수·1차 대비 변화. 한 문장 더 고치면 "최종 검토 이후 수정 1건" | 1회가 기본, 다시 받기는 선택(횟수 기록). 재검토 무제한을 대체(ADR 0011) |
| ⑥ 최종 마무리 | 선택형 확정, 제안자 정보 입력(저장 안 됨), 점검 목록, HWPX 다운로드 | 양식 파일은 이 경로로만. 체크 칸은 확정값으로만 |
| 부록 | run 목록·자료 검색·자료원 상태, manifest(전송 doc_id·건수만) | 무엇을 외부에 보냈는지 항상 남는다 |

말하지 않을 것: 사내 과제명·개인 이름. 화면에 뜨는 사내 자료 제목은 공시된 것만 쓴다.
