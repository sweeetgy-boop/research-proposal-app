# 예상 질문과 답

**Q. 사내 자료가 외부 LLM 으로 나가지 않나?**
작성은 로컬(Qwen 7B, 127.0.0.1)만 쓴다. Gemini Argon 검토에는 초안 문장과 인용된 근거 구간만 보내며, 사내(internal) 자료를
보낼지는 `llm.yaml external_llm.include_internal` 로 정한다(끄면 그 근거를 인용한 문장은 "검토 제외"). 보낸 doc_id·문장 수는
manifest 에 남고 사람 이름·연락처는 모델에 보내지 않는다(ProposerInfo 는 렌더 인자로만).

**Q. 모델이 지어낸 내용은 어떻게 막나?**
근거 id 가 검색 집합 밖이면 문장 폐기, 정책·계획명은 제안자 입력에 있는 것만(grounding), 입력·근거에 없는 수치는 경고 +
검토 지적 의무 + 마무리 점검 맨 위 건수. 검토 LLM 의 수정안·추가 문장도 같은 검증을 통과해야 반영된다.

**Q. 유사과제 판정 정확도는?**
유사도(e5) AND 공유 키워드 2개 이상(일반어 제외). 골든셋 3건에서 무관한 아이디어(도서관)는 알림 0, 자산개발 아이디어는
사내 공시 요약을 차단 알림. 최종 판단은 담당자가 하고 앱은 "확인했습니다" 를 받아야 생성한다.

**Q. 비용과 속도는?**
로컬 작성은 비용 0, 12개 섹션 105~145초(M-시리즈 Mac). Argon 검토는 건당 1회(약 36초). 하루 제안서 수십 건이면 Gemini 수십 호출.

**Q. 왜 Streamlit 이 아니라 웹 SPA 인가?**
문장 단위 편집·diff·팝업·접근성(WCAG 2.2 AA, Lighthouse 95)은 SPA 가 맞다(ADR 0008). Streamlit 은 시연·내부용으로 남긴다.

**Q. 운영은?**
Mac mini + launchd 4종(mlx·api·백업·야간 적재). 공개 방식(Tailscale/Cloudflare)은 비교 문서만 있고 결정 대기. 백업은 매일 7벌.

**Q. 양식이 바뀌면?**
run 은 생성 때의 양식 id·섹션 순서를 기억한다. 양식이 바뀌면 이전 run 은 조회만, 재생성은 `--reuse-input`. 템플릿 스크립트는
앵커 불일치로 멈춰 사람이 확인한다.

**Q. 평가 결과가 바뀌면 자동으로 학습하나?**
아니다. 골든셋 피드백 루프는 이슈 #10 으로 남겨 두었고, 임계치·프롬프트 변경은 측정(`rra eval`)과 ADR 을 거친다.

**Q. 어떤 것이 아직 안 됐나?**
`limitations.md`.
