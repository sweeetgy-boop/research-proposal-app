# 시범 운영 안내 (동료용, 2026-10-28 ~)

연구과제 제안서 작성 지원 앱(RRA)을 3명이 시범으로 씁니다. 아래 순서대로 접속하고, 막히면 "오류·개선점 기록" 방법대로 남겨 주세요.

## 1. 접속

| 단계 | 내용 |
|---|---|
| ① 주소 | **`https://rra.taile5afcf.ts.net`** (2026-10-28 현재, Tailscale Funnel 공개 주소). 브라우저만 있으면 됩니다 — **Tailscale 앱 설치·초대 수락은 필요 없습니다**. 사무실 운영 맥에서는 `http://127.0.0.1:8000` |
| ② 앱 로그인 | 탭 **철도연구원 직원(사번)**: 사번만 입력 / 탭 **그 외 사용자(아이디·비밀번호)**: 공용 아이디 `korail` + 비밀번호 |

- 사번·비밀번호를 5회 연속 틀리면 그 계정이 10분 잠깁니다. 메시지는 한 가지("사번 또는 아이디·비밀번호를 확인하세요")만 나옵니다.
- 세션은 12시간입니다. 오른쪽 위 로그아웃으로 끝낼 수 있습니다.
- 회사 도메인 주소(`rra.ai-edu-lab.co.kr`, Cloudflare 이메일 코드)는 DNS 이전 뒤에 엽니다. 그때까지는 위 ts.net 주소만 씁니다.

## 1.5 접속이 안 될 때 (2026-10-28)

먼저 **휴대폰 데이터망(와이파이 끔)** 으로 같은 주소를 열어 보세요. 휴대폰에서는 열리고 회사 PC 에서만 안 열리면 회사망이
`*.ts.net` 또는 Tailscale 중계 서버를 막고 있을 가능성이 큽니다 — 그 결과(열림/안 열림, 시각)를 운영자에게 알려 주세요.

| 증상 | 확인할 것 | 대처 |
|---|---|---|
| 페이지가 아예 안 열림(시간 초과·"사이트에 연결할 수 없음") | 휴대폰 데이터망에서는 열리는가 | 휴대폰에서 열리면 회사망 차단 → 당분간 휴대폰 테더링·집 인터넷으로 접속, 운영자가 정보보안 담당에 `rra.taile5afcf.ts.net`(443) 허용 요청. 휴대폰에서도 안 열리면 운영자에게 — 서버(맥) 꺼짐·Funnel 꺼짐 |
| 인증서 오류("연결이 비공개로 설정되어 있지 않음" 등) | 주소 철자(`taile5afcf`), 회사 보안 프로그램의 HTTPS 검사 | 주소를 다시 입력. 철자가 맞는데 회사 PC 에서만 나면 회사 보안 장비가 가로채는 것 → 휴대폰으로 확인 후 운영자에게. 경고를 무시하고 넘어가지 마세요 |
| "사번 또는 아이디·비밀번호를 확인하세요" | 사번을 정확히 넣었나(공백·하이픈은 상관없음), 등록된 사번인가 | 운영자가 `rra auth staff check` 로 등록 여부를 확인합니다(§6.1). 5번 틀렸으면 10분 뒤 다시. 공용 계정은 아이디 `korail`·비밀번호를 운영자에게 다시 확인 |
| "요청 출처가 허용되지 않습니다"(403) | 주소창이 위 주소와 정확히 같은가(다른 주소·북마크로 들어옴) | 위 ① 주소로 다시 접속 |
| 로그인은 되는데 화면이 비거나 계속 돎 | 새로 고침(Ctrl+Shift+R) | 그래도 그러면 시각과 함께 운영자에게 (서버 로그로 확인) |

운영자 점검 순서(이 맥은 tailnet 안이라 그냥 `curl` 하면 내부 경로로 가서 공개 경로 문제를 못 봅니다):

```
/Applications/Tailscale.app/Contents/MacOS/Tailscale funnel status      # 443 에 "(Funnel on)" 이 있어야 함
dig +short rra.taile5afcf.ts.net @1.1.1.1                               # 공개 진입 IP
launchctl list | grep com.rra && curl -s http://127.0.0.1:8000/healthz
grep "api.access\|api.login.fail\|api.auth.reject" ~/Library/Logs/rra-api.err.log | tail -50   # 4xx·로그인 실패(값 없음)
```

- Funnel 이 꺼져 있으면 운영자가 직접 `… funnel --bg --https=443 http://127.0.0.1:8000`. 배포 스크립트는 Funnel 을 확인만 하고 바꾸지 않습니다.
- 공개 경로는 **이 맥 밖**(휴대폰 데이터망, 또는 외부 점검 사이트 check-host.net 의 HTTP 점검)에서 `https://rra.taile5afcf.ts.net/healthz` 가
  `{"status":"ok",…}` 인지로 확인합니다. 이 맥에서 하는 `curl`·`tools/deploy.sh` 외부 확인·Claude 의 WebFetch 는 모두 tailnet 경로라
  Funnel 이 밖에서 막혀도 ok 로 보입니다. 앱 로그 `api.access … ip=100.74.2.113`(이 맥의 Tailscale 주소)는 tailnet 경로로 온 요청입니다.
- **Funnel on 인데 밖에서 "Broken pipe"·TLS 끊김**(2026-10-28 실제 증상 — 공개 진입 IP 2개 모두, 4개국 점검 노드 전부): Funnel 중계가 이 맥으로
  넘기지 않는 상태입니다(중계 노드와 주고받은 바이트 0). 운영자가 순서대로: ① `… funnel --https=443 off` → `… funnel --bg --https=443 http://127.0.0.1:8000`
  ② 안 되면 Tailscale 앱 종료·재실행(메뉴 막대) ③ 관리 콘솔(login.tailscale.com) Access controls 의 `nodeAttrs` 에 `funnel` 이 이 맥(또는 사용자)에
  붙어 있는지, DNS 에서 HTTPS Certificates 가 켜져 있는지 확인 ④ 1~2분 뒤 밖에서 다시 확인.
- 로그인 IP 잠금은 접속자 IP(Funnel 이 넘겨주는 `X-Forwarded-For` 맨 오른쪽, 127.0.0.1 에서 온 요청일 때만)로 겁니다. 접속자 IP 를
  모르면 IP 잠금은 걸지 않습니다(계정별 잠금·전체 지연은 그대로). 잠금은 메모리에만 있어 API 재시작 때 풀립니다.

## 2. 사용 순서 (2026-10-28 저녁 개정)

화면 위쪽 단계 표시(아이디어 입력 → 유사과제 확인 → 초안 생성 → 직접 수정 → 최종 검토 → 최종 마무리)를 누르면 그 화면으로 갑니다.
아직 닿지 않은 단계는 눌리지 않고 이유("초안 생성 후 열립니다" 등)가 보입니다. run 화면 맨 위에는 과제 제목이 크게, run 번호는 그 아래 작게 보입니다.

1. **입력** — 연구 아이디어(과제명·배경·목표 등)를 적고 필수 칸을 채웁니다. 간편 입력도 됩니다.
2. **유사과제 확인** — 사내 과제·국가R&D 와 비교하고, 위쪽 후보 10건은 **Argon 이 "대상·문제·방법이 실제로 같은가"를 판정**합니다. "같다"일 때만
   차단이고, 표에 판정 이유가 한 줄 붙습니다(판정이 실패하면 "규칙 기준"으로 표시되고 [다시 시도]가 있습니다). 제목만 같은 중복 과제는 한 줄로 합칩니다.
   - 행마다 **[유사함] / [관련 없음]** 을 고르세요. [유사함]으로 고른 과제만 **차별성 비교표**·활용 제안·**차별화 과제안**·본문 5. 특이사항에 쓰입니다.
     차단 과제를 모두 [관련 없음]으로 고르면 차단이 풀립니다(고른 기록은 기준 조정에 쓰고 개인정보는 남기지 않습니다).
   - **차별화 과제안** 2~5개 카드(과제명·목표·방법·적용범위·기존 과제 대비 차이·근거): [이 안으로 진행] / [원래 아이디어 유지] / [직접 작성].
     고르면 칸마다 고칠 수 있고 [AI로 다듬기](그 칸만)도 됩니다. 고른 내용이 초안 입력이 됩니다(원래 안·고른 안·고친 안은 버전으로 남음).
   - "다음" 버튼이 눌리지 않으면 옆에 이유가 보입니다(예: "차단 경보를 확인해 주세요").
   - 실시간 검색(ScienceON·NTIS·OpenAlex)도 함께 돌아 "실시간 검색" 배지·자료원별 상태가 보입니다.
3. **보강 질문** — Argon 이 빠진 정보를 2~4개 묻습니다(정책 근거·예산·기간·적용 대상·정량 목표 등). 답은 "보충 정보"로 초안에 들어갑니다.
   질문이 없으면 이유(꺼짐 / 생성 실패 — [다시 시도] / 입력 충분)가 보입니다.
   - 정책 근거를 적지 않았으면 **정책적 중요도 작성안**이 최대 4개 나옵니다(정부 계획 / 공사 전략 / 감사 지적·현안 / 지역·사회 정책). 카드마다 출처(문서명·연도·
     원문 인용·링크)가 있고 본문은 인용 문구 안에서만 씁니다. [이 안으로], 두 안 합치기, 고른 뒤 직접 수정·[AI로 다듬기], [직접 작성], [정책 근거 없음으로 진행].
     "없음"으로 진행하면 2-가-(1)은 비고 "정책 근거 확인 필요" 알림이 제출 전 점검에 남습니다.
4. **생성** — 12개 섹션을 Argon 이 먼저 씁니다(4개씩 동시). 실패한 섹션만 로컬 모델이 쓰고 "로컬 작성" 배지가 붙습니다.
5. **직접 수정** — 문장·섹션을 고치고 [새 버전으로 저장]. 버튼은 늘 눌리고, 바뀐 것이 없으면 "변경된 내용이 없습니다. 최종 검토로 넘어갈까요?"를 묻습니다.
   "변경 n건"에는 문장·섹션 편집, 그림 동작, 근거 판단, 선택형 값, 정책 근거, 보완 메모가 모두 들어갑니다.
   - **AI 다시 쓰기**: Argon 이 같은 지시·근거로 다시 씁니다(빈 섹션은 새로 씁니다). 후보가 없으면 이유와 [다시 시도]가 보입니다. 직접 고친 문장과 선택형 값은 그대로 둡니다.
   - **보완 질문**: Argon 이 섹션을 읽고 빠지거나 약한 부분을 2~4개 묻습니다. 답한 뒤 [답 반영해 다시 쓰기]로 바로 다시 쓸 수 있습니다.
   - **그림**: 기본은 As-Is/To-Be 1장(+ 검증된 통계가 있으면 수치 그래프, 연구기간이 있으면 일정표)과 **분석 기법 추천 0~2장**(SWOT·퓨 매트릭스·비용-편익 등
     20개 중 이 제안서에 맞는 것, "추천" 배지와 이유 한 줄). 추천 그림은 [넣기 확정] / [필요 없음](아래에 접어 둠, 다시 넣기 가능) / [다른 기법으로 바꾸기].
     결정하지 않은 추천은 제출 전 점검에 뜨고, 그대로 마무리하면 넣은 채로 나갑니다. 개념도·체계도·로드맵은 [다른 그림 추가]에서 고를 수 있습니다.
   - 단계 표시로 ①·②로 돌아가 입력·유사과제 선택·과제안·정책 근거를 바꾸면 저장할 때 [보기만 하고 돌아가기] / [바뀐 내용과 관련된 섹션만 다시 쓰기(새 버전)] /
     [초안 전체 다시 생성(새 버전, 기존은 이전 버전으로 보존)] 중에서 고릅니다.
6. **최종 검토** — Argon 최종 검토 1회. 점수·의견을 보고 더 고칠지 정합니다.
7. **제출 전 점검 → 마무리** — 알림은 한국어 설명으로 보입니다. 근거 "확인 필요"는 불일치·부분 지지 판정 문장과 이미지 판독 근거만 세고, 나머지는
   [근거 일괄 승인]으로 처리합니다. 선택형은 AI 제안값을 [제안값 그대로 확정]하거나 바꿉니다. 내려받는 파일 이름은 `과제 제목_v<번호>.hwpx` 입니다.
   양식 파일은 본문 12pt·줄 간격 160%, 장 제목 13pt, 가./(1)/○/- 단계마다 내어쓰기가 맞춰지고(줄이 넘어가도 글머리표 뒤에 정렬), 그림 캡션·출처는 12pt 가운데입니다.

## 3. 알려진 제약

- 생성은 **동시에 3건**까지 돕니다(대기는 사용자별 6건까지). 3건이 함께 돌면 각자 조금 느려집니다(1건 약 4분, 2026-10-28 실측: 혼자 평균 107초, 셋이 함께 240초).
- 한 건 소요(2026-10-28 저녁 실측, 골든셋 10건): 유사과제 확인 **36~76초**(실시간 검색 + AI 같음 판정 + 과제 추천, 중앙 약 43초)
  → 생성 평균 105초(92~124초) → 최종 검토 약 15초 → 다운로드 1초. 생성 결과 10건 모두 유효, 빈 초안 0, HWPX 서식 점검 10/10.
- AI 다시 쓰기·보완 질문은 한 번에 보통 5~20초입니다. Argon 응답이 늦으면 몇 분 걸릴 때가 있습니다(기다리기 싫으면 창을 닫고 [다시 시도]).
- 일일 생성 상한: 직원 1인 20건, 공용 계정 10건. Argon(Gemini) 일일 상한은 전체 600회(초안 1건 약 15회)이고, 넘으면 섹션을 로컬 모델이 대신 씁니다
  ("로컬 작성" 배지, 조금 느림). 그림은 하루 150장까지이고 넘으면 기본 그림이 들어갑니다.
- 공용 계정(아이디·비밀번호)은 사내 비공개 자료(internal)를 검색·근거·추천에서 뺍니다. 직원 로그인은 전부 봅니다.
- NTIS(국가R&D) 자료는 서버 IP 등록 문제로 빠질 수 있습니다(2026-10-28 현재 실시간 검색에서 NTIS 는 "IP 차단"). 빠지면 유사과제 화면 자료원별 상태에 안내가 뜹니다.
- 실시간 검색으로 찾은 논문·보고서·과제는 공개 자료로 저장되어 다음 사람의 검색에도 쓰입니다(개인 이름은 빼고 저장).
- 서버는 사무실 맥(MacBook/Mac mini) 한 대입니다. 꺼지거나 절전이면 접속이 안 됩니다.
- 생성 결과는 초안입니다. 수치·정책명은 근거를 꼭 확인하세요(미확인 수치는 알림으로 표시됩니다).

## 4. 오류·개선점 기록 방법

아래 4가지를 적어 공유 채널(또는 저장소 이슈)에 남겨 주세요. **사번·비밀번호는 적지 않습니다.**

1. 화면 단계(① 입력 ~ ⑥ 다운로드 중 어디)
2. 입력 요약(과제명 정도, 개인정보 없이)
3. 시각(분 단위)
4. 화면 캡처(오류 문구가 보이게)

  `rra.api.access`(상태·경로·IP만), 로그인 실패는 `api.login.fail kind=… ip=…`(사번·아이디 값 없음) — 모두 `rra-api.err.log`
- 상태 확인: `launchctl list | grep com.rra`, `curl http://127.0.0.1:8000/healthz`, `rra sources status`

## 5.5 그림(인포그래픽) 안내 (2026-10-28 저녁 개정)

- 그림은 초안 내용을 구조화한 "명세"로만 그립니다(본문·입력·검증된 근거에 있는 글자·숫자만). Nano Banana Pro 가 색·아이콘·제목 위계를 살린
  인포그래픽으로 그리고, 실패하면 템플릿 밑그림("기본 그림" 배지)이 들어갑니다. 상자 글자는 1~2줄로 줄여 크게 씁니다.
- **As-Is/To-Be**: 왼쪽 현재(현황·원인·한계, 회색·주황), 오른쪽 연구 후(목표·해결 방안·기대효과, 파랑·초록), 가운데 화살표에 핵심 해결 방법 한 줄.
  2-나 연구목적 뒤에 들어갑니다(양식에 "연구배경" 칸이 없어 연구목적, 비면 기술적 중요도 뒤).
- **분석 기법 추천**: 정성 기법(SWOT 등)은 상·중·하, 비교·평가 기법(퓨·AHP 등)은 +/0/− 또는 상·중·하로 매기고 그림에 "제안 내용 기반 예비 평가"가
  붙습니다(판단으로 매긴 평가). 경제성 기법은 제안서·근거에 있는 숫자로만 계산하고, 없으면 "산출 필요"로 둡니다. 카드에서 항목마다 어느 문장·근거에서
  왔는지 볼 수 있습니다.
- 그림마다 "확인 전/확인함" 배지가 있습니다. **AI 가 그린 그림입니다. 숫자와 글자를 원문과 확인하세요.** 큰 글씨에서 글자가 뭉개지는 경우가 있었습니다.
- [말로 고치기]는 요청을 그림 명세 변경으로 바꾸고 밑그림에서 새로 그립니다. 고칠 수 없는 요청이면 이유를 한국어로 알려 줍니다.
- 그림 호출은 하루 150회(생성·고치기 포함)입니다. 넘으면 기본 그림이 들어갑니다.

## 6. 계정 관리 (운영자만)

사번·비밀번호는 화면·로그·저장소 어디에도 원문이 남지 않습니다(사번은 HMAC, 비밀번호는 scrypt, `data/auth/` 700/600). 저장소 루트에서 실행합니다.

### 6.1 사번 일괄 등록 (`rra auth staff import`)

인사 명부(xlsx 또는 csv)에서 **"사번" 열만** 읽어 등록합니다. 다른 열(이름·부서 등)은 격리된 자식 프로세스에서 버려지고 본체에 오지 않습니다. 원본 파일은 복사하지 않습니다(저장소·`data/` 밖에 두어도 됩니다). 출력은 개수뿐이며 사번 값은 오류 행도 행 번호만 나옵니다.

```
.venv/bin/rra auth staff import --file ~/Downloads/사번_전체.xlsx --dry-run      # 1) 집계만 보고 저장 없음
.venv/bin/rra auth staff import --file ~/Downloads/사번_전체.xlsx                # 2) 기존 목록에 추가
.venv/bin/rra auth staff import --file ~/Downloads/사번_전체.xlsx --replace      #    기존 목록을 이 파일로 교체
.venv/bin/rra auth status                                                      # 3) 등록 수 확인
```

| 옵션 | 뜻 |
|---|---|
| `--file <경로>` | `.xlsx` 또는 `.csv`(utf-8·cp949). `.xls` 는 엑셀에서 xlsx 로 다시 저장 |
| `--sheet <이름>` | 시트 지정(기본: 첫 시트) |
| `--column <열 제목>` | 열 제목이 "사번"이 아닐 때(앞쪽 8행 안에서 찾음) |
| `--pad <자릿수>` | 엑셀이 숫자로 저장해 앞자리 0 이 빠진 사번을 이 자릿수까지 0 으로 채움 |
| `--replace` | 기존 등록 목록을 이 파일로 바꿈(없으면 추가). 파일 안 중복은 하나로 합침 |
| `--dry-run` | 저장 없이 같은 집계만 |

- 정규화: 앞뒤 공백·하이픈 제거, 문자열로 처리. 로그인 입력도 같은 규칙이라 `00-123-45` 와 `0012345` 는 같은 사번입니다.
- 출력의 **길이별 분포**("5자리 2건, 7자리 40건")로 0 빠짐을 알아챕니다. 길이가 섞여 있으면 `--pad <원래 자릿수>` 로 다시 실행하세요(이미 등록된 짧은 값은 `--replace` 로 정리).
- 저장되면 **API 재시작 없이** 다음 로그인부터 반영됩니다(로그인마다 `data/auth/staff.json` 을 읽습니다).
- 한 명씩: `rra auth staff add|remove`(화면에 안 보이는 입력), 개수 `rra auth staff count`.
- 등록 여부 확인: `rra auth staff check` — 사번을 화면에 안 보이게 입력받아 **"등록됨" 또는 "미등록"만** 출력합니다(로그인과 같은 정규화). 동료가 로그인이 안 된다고 할 때 씁니다.

### 6.3 배포 (시범 기간 규칙, 2026-10-28)

**규칙**
- PR 을 main 에 합쳐도 운영 API 를 **자동으로 재시작하지 않는다**. 반영할 PR 은 `docs/history/deploys/pending.md` 에 한 줄씩 쌓아 둔다.
- 운영자가 "배포해" 하면 아래 스크립트로 한 번에 반영한다. 생성 중인 동료가 있으면 끝날 때까지 기다린다(`--wait`).
- 예외: **보안 수정, 로그인·접속이 막히는 오류 수정**은 합친 즉시 배포하고 운영자에게 알린다.
- 화면 하단에 `버전 <커밋 7자> · 배포 <월-일 시:분>` 이 보인다(로그인 전에도). 동료가 어떤 버전을 쓰는지 이것으로 확인한다.
  같은 값은 `curl -s http://127.0.0.1:8000/healthz` 의 `version` 에도 있다.

**절차** (저장소 루트, main)
```
git checkout main && git pull
tools/deploy.sh --dry-run        # 1) main 최신·web 변경·생성 중 run 확인만 (재시작 없음)
tools/deploy.sh --wait           # 2) 생성이 끝날 때까지 기다렸다가 반영 (최대 30분, --wait-max 초)
```
스크립트가 하는 일: main 이 origin/main 과 같은지 → `web/` 이 지난 배포 이후 바뀌었으면 `npm run build` → 대기·실행 중인 생성
run 확인(`rra runs active`; 있으면 `--wait` 대기, `--force` 는 무시하고 진행 — 그 run 은 interrupted 가 된다) →
`data/deploy/version.json` 기록 → `launchctl kickstart -k gui/$(id -u)/com.rra.api` → `/healthz` 가 새 커밋을 보고하는지,
`/login` 이 200 인지, 외부 주소(`https://rra.taile5afcf.ts.net`, `RRA_DEPLOY_EXTERNAL_URL` 로 변경) 확인 →
`docs/history/deploys/<시각>.md` 기록과 `pending.md` 비움(이 두 파일은 docs PR 로 커밋).

| 옵션 | 뜻 |
|---|---|
| `--dry-run` | 확인만. 빌드·재시작·기록 없음 |
| `--wait [--wait-max 초]` | 생성 run 이 끝날 때까지 20초 간격으로 기다림(기본 최대 1800초) |
| `--force` | 생성 run 이 있어도 재시작(그 run 은 interrupted) |
| `--no-build` / `--no-external` | web 빌드 생략 / 외부 주소 확인 생략 |

실패하면 `~/Library/Logs/rra-api.err.log` 와 `launchctl list | grep com.rra.api` 를 본다. 이전 버전으로 되돌리려면
`git checkout <이전 커밋>` 뒤 `tools/deploy.sh --force` 가 아니라, main 을 되돌리는 PR(revert)을 합친 뒤 같은 절차로 배포한다.

### 6.4 그림 기능 끄고 켜기 (2026-10-28)

그림은 `config/figures.yaml` 의 `enabled` 로 켜고 끕니다(기본 켬). 끄면 초안 생성의 그림 단계, 1차 검토의 그림 전송, HWPX 그림 삽입이 모두
빠지고 나머지는 그대로입니다. 설정은 API 가 뜰 때 읽으므로 **바꾼 뒤 API 를 다시 띄워야** 반영됩니다.

**긴급히 끄기** (그림 때문에 생성이 막힐 때, 저장소 루트):
```
sed -i '' 's/^enabled: true/enabled: false/' config/figures.yaml
launchctl kickstart -k gui/$(id -u)/com.rra.api
curl -s http://127.0.0.1:8000/healthz                      # {"status":"ok", ...}
```
다시 켜기는 `false` → `true` 로 바꾸고 같은 두 줄을 실행합니다.

- 이 방법은 추적 파일(`config/figures.yaml`)을 고친 상태라 `tools/deploy.sh` 가 "추적 파일에 변경이 있습니다"로 멈춥니다. 정식으로 바꾸려면
  `enabled` 변경을 PR 로 합친 뒤 `tools/deploy.sh` 로 배포하고, 긴급 변경은 `git checkout config/figures.yaml` 로 되돌린 뒤 배포합니다.
- 꺼 둔 동안 만든 run 에는 그림이 없고, 이미 만든 그림은 버전에 남아 있습니다(켜면 다시 보임). 그림 호출 수는 `.venv/bin/rra runs figures <run_id>`.
- 하루 그림 호출 상한은 같은 파일의 `daily_image_cap`(150), 오늘 쓴 수는 `data/cache/figure_budget.json` 의 `count`.
