## 무엇을 쟀나
- 운영 DB 사본 두 개(scratch, SQLite backup API 로 복사 — 운영 DB 는 읽기만): **전** = 이주 전 DB + `origin/main` 의
  `config/retrieval_mix.yaml`, **후** = `rra db reclassify --apply` 를 적용한 사본 + 이 브랜치의 설정.
- 골든셋 6건(01 궤도 틀림·02 자산개발·04 전차선 아크·08 수요 예측·09 역 주차·10 분산에너지). 생성은 하지 않고

  정책 근거 추천은 `PolicySuggest`(LLM 없음).
- LLM·Gemini 호출 0회. 임베딩·reranker 는 `tools/with_heavy_lock.py` 안에서, `rra runs active` 0건 확인 뒤.

## 판단·후속
- 공사 홈페이지 묶음(korail_web)은 검색 상한(작성안 방향당 12청크) 안에서 보도자료·이미지 판독·연구용역·행정 공시와 자리를 다툰다 —
  공사 정책 구간이 0~3건에 그치는 이유. 저장소 `hybrid_search` 에 doc_type 필터를 더하면 늘릴 수 있다(포트 변경, 후속).
- 2-가-(3) 에 공사 경영목표 문서를 넣으려면 2-가-(3) 섹션 질의(전략 목록 이름 + 아이디어)를 `section_search` 에 더한다(후속).
