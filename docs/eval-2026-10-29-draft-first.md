# 초안 글 먼저, 그림은 백그라운드 — 실측 (2026-10-29 아침, 레인 C, ADR 0045)

## 측정 방법

- 코드: 브랜치 `feat/draft-first-figures-bg`(PR #97). 측정 전용 API 포트 8043, 원 저장소 config 사본(`RRA_CONFIG_DIR`, Gemini 카운터
  `data/cache/llm_budget_lane3C.json` 상한 80·그림 카운터 `figure_budget_lane3C.json` 상한 40), run 은 측정 전용 폴더(`RRA_RUNS_DIR`,
  미커밋). 로컬 모델 슬롯(`.generate.lock`)은 운영 것과 같은 파일(하드 링크)을 썼다. `max_image_redraws` 는 main 그대로 2.
- 순서: ② 는 생략하고 `POST /v1/runs`(acknowledged) → `GET /v1/runs/{id}` 1초마다. 서버 값 `draft_visible_seconds`(제출 → drafted,
  화면에 초안 글이 보이는 때)·`figures_done_seconds`(제출 → 그림 모두 끝)와 클라이언트 시계(차이 0.5초 안)를 함께 적었다.
- 매번 `rra runs active` 0건 확인, 무거운 작업 잠금(`tools/with_heavy_lock.py`) 안에서. 동료 run 은 내내 0건.
- 아이디어: 골든셋 01(궤도 틀림)·02(자산 개발)·03(무관 대조군) — 지난 측정(docs/eval-2026-10-28-pilot2.md)과 비교하려고 같은 셋.

### 예산과 측정 사고

- 첫 3건 동시 시도는 측정 환경 잘못으로 마무리 단계에서 끊겼다(로컬 슬롯 파일을 심볼릭 링크로 걸었는데, 락은 `O_NOFOLLOW` 라
  `OSError`). 섹션은 다 써서 Gemini 32회를 썼다. 앱 결함이 아니다(하드 링크로 고침).
- 남은 48회로: 단건 01·02 를 새로 돌리고(각 14~18회), 끊긴 3건은 **이어 하기**(섹션은 저장돼 있어 마무리·L2·그림만)를 동시에 돌렸다.
  동시 3건의 "초안 보임" 은 끊기기 전 기록(검색·섹션 시각) + 이어 하기의 마무리 시간으로 계산한 값이다(아래 표의 "추정").
- 단건 02 의 마지막 호출에서 카운터가 80 에 닿았다 — 그 run 의 분석 기법 추천은 "규칙에 걸러짐"(technique_groups)으로 끝나 그림 2장.
- 03 단건은 예산이 없어 돌리지 못했다.

- 단건 01 섹션 95초: Argon 섹션 작성 11회 중 한 번이 **79.3초**(나머지 4~25초). 시간 제한이 없으니 가장 느린 섹션이 초안 보임을 정한다.
- 단건 01 마무리 83초: L2 로컬 2차 검토(로컬 모델). 지난 측정 12.5~38.8초보다 길다. 같은 시간대 다른 레인의 로컬 모델 사용과 겹쳤을 수 있다.
- 동시 3건은 검색 끝(48초) → 섹션 시작(86~89초) 사이 약 40초가 섹션별 맞춤 검색(Q3)·재순위였다(세 run 이 함께).

## 결론

- 초안 글이 보이는 시간은 그림 단계만큼 줄었다: 단건 −46초(01)·−116초(02), 동시 3건 −101~−120초(추정).
- 120초 기준은 Argon 섹션 작성의 느린 한 번(79초)과 L2(83초)가 있으면 넘는다. 다음 후보: L2 를 초안 뒤로 미루기(지금은 초안 전에 알림을
  붙인다), 섹션 작성 동시 수(compose.concurrency 4)·느린 섹션만 따로 보이기 — 이 PR 에서는 하지 않았다(소유자 판단).
- 그림 작업은 동시 3건에서도 겹쳐 돌았고, 편집·상태 표시와 부딪치지 않았다(가짜 테스트·e2e 로 확인).
